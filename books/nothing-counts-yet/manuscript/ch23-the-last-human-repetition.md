# Chapter 23 — The Last Human Repetition

Every automation proposal contains a hidden question:

Which repetition should a human do for the last time?

The obvious answer is the boring one.

The tedious form.

The duplicate entry.

The mechanical calculation.

The boilerplate paragraph.

The routine classification.

The task that consumes attention without deserving it.

Human history is full of progress created by removing repetition.

Nobody should preserve drudgery merely because repetition can teach.

But some repetitions are carrying more than output.

They are building perception.

The apprentice radiologist looks at many ordinary images partly so the abnormal image becomes abnormal to the eye.

The junior engineer reads logs until patterns acquire shape.

The editor reads mediocre sentences until rhythm becomes diagnostic.

The cook repeats cuts until the hand knows distance.

The musician repeats scales until attention can move elsewhere.

The salesperson hears ordinary objections until the unusual hesitation becomes audible.

Repetition can convert explicit attention into background capability.

Automation can remove the task before we notice that the task was also the training distribution.

This creates a difficult design problem.

Suppose a machine can perform the routine cases better, faster, and cheaper than a novice.

Production logic says give the cases to the machine.

Training logic says the novice may need those cases before being trusted with the unusual ones.

But it would be absurd to make customers wait for worse service merely to educate future workers if a safer alternative exists.

So the institution needs to separate production from preparation.

If reality no longer supplies enough repetitions, manufacture them.

Build a case library.

Replay historical scenarios.

Generate synthetic variations.

Ask the learner to classify before revealing the machine's answer.

Insert difficult edge cases.

Require explanation.

Track whether recognition transfers to unseen examples.

In other words, automation makes simulation more important.

The machine removes accidental apprenticeship.

The organization must replace it with deliberate apprenticeship.

This principle extends beyond professions.

Navigation software removed a great deal of wayfinding practice.

Autocomplete removes some spelling retrieval.

Recommendation systems remove some searching.

Generated summaries remove some reading.

Automatic photography removes some technical camera decisions.

AI coding tools remove some encounters with syntax and boilerplate.

Each trade can be worth making.

The question is not whether an old skill deserves ceremonial preservation.

The question is whether another capability depended on the old repetition as substrate.

When the substrate disappears, what else disappears with it?

Sometimes the answer is nothing important.

Good. Automate it.

Sometimes the answer is a capability we still need.

Then we have to rebuild the repetition somewhere else.

This is especially urgent when experts are expected to supervise machines.

Supervision sounds easier than production.

Often it requires deeper judgment.

The supervisor must notice the rare case where the automated output is wrong.

But rare cases are exactly the cases a novice encounters least often if automation handles the ordinary flow.

We can accidentally create a role that requires expert discrimination while deleting the experiences through which expert discrimination used to form.

This is the automation paradox of apprenticeship.

The better the machine becomes at routine work, the less routine work remains available to train the humans expected to catch the machine's non-routine failures.

The solution cannot be “keep humans busy.”

It must be “keep humans learning.”

Those are different objectives.

A well-designed future job may contain fewer productive repetitions and more explicitly developmental ones.

Ten minutes of carefully selected practice cases before a shift.

A weekly simulation of rare failures.

A machine that occasionally asks the human to predict before showing its recommendation.

A review system that surfaces surprising disagreements rather than only measuring throughput.

Rotations through edge cases.

Counterfactual exercises: what would you do if the tool were unavailable or if this input were corrupted?

This sounds inefficient only if training is treated as overhead.

Once routine work stops training people accidentally, training becomes visible as a cost.

The cost was always there.

It was hidden inside production.

Automation reveals the invoice.

This may become one of the defining management challenges of the AI era.

Not how to automate every repetitive task.

How to identify which repetitions were secretly creating the judgment we still expect humans to possess afterward.

There is no universal answer.

A child should probably learn some arithmetic even though calculators exist because numerical intuition matters beyond manual calculation.

A professional writer may not need to hand-copy prose as earlier generations sometimes did.

A programmer may need less syntax recall and more architecture, debugging, verification, and systems judgment.

A doctor may need fewer clerical repetitions and more diagnostic rehearsal.

The curriculum should move as the tool moves.

But it must move.

Otherwise automation can produce a strange society: extraordinary outputs resting on a shrinking base of people who understand how those outputs become trustworthy.

The last human repetition should therefore be chosen deliberately.

Before deleting a task, ask:

What did doing this repeatedly teach?

Do we still need that capability?

If yes, where will the repetitions come from now?

Then automate without nostalgia.

The goal is not to preserve old work.

It is to preserve the human capacity that worthwhile automation should free, not quietly consume.

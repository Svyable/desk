# Friction by Design

The door that opens too easily is not always a better door.

Sometimes the resistance is the information.

A surgeon pauses before the incision.

A pilot reads the checklist before takeoff.

A trader hits a confirmation screen before sending an order large enough to matter.

A journalist asks another editor to read the accusation before publication.

A software deployment stops because one test failed.

These are small acts of designed inconvenience.

Nobody installs them because delay is beautiful.

They exist because the cost of interruption is lower than the cost of an unexamined action.

Artificial intelligence has entered the world with the opposite design instinct.

Remove friction.

Fewer clicks.

Faster answers.

One sentence in, finished artifact out.

Automatic completion.

Automatic action.

This instinct makes sense. Most software has spent decades fighting pointless effort. Users hate forms, repetitive entry, unnecessary approvals, menus inside menus, and systems that make people carry information the computer already has.

The danger is that useful friction looks identical to useless friction if the only metric is speed.

The new workshop needs a distinction.

Friction should disappear where it protects nothing.

Friction should increase where it creates judgment.

That is the premise of friction by design.

The phrase sounds like a contradiction because product design treats friction as the enemy. In a safety system, friction is often the point.

A good guardrail slows the wrong action.

A good review gate forces the right question.

A good warning appears when the consequence becomes hard to reverse.

A good apprentice knows when not to proceed.

Agents need the same structure.

The first generation of AI assistants trained people to expect conversation. Ask, answer, revise. The human remained physically present because the system usually lacked authority to do much outside the chat.

Agents change that.

They can open files, change code, call services, send messages, move information, create records, schedule work, and operate through longer sequences. The value comes from not having to approve every step.

So does the risk.

A workshop that requires human confirmation after every harmless action is not agentic. It is a remote-control interface with a very articulate cursor.

A workshop that never interrupts can move quickly in the wrong direction.

We need to place the pauses.

One way is to think in terms of reversibility.

If an action is cheap to undo, the agent can usually have more freedom.

Drafting a private note is reversible.

Generating candidate code on a branch is reversible.

Creating a local analysis is reversible.

Sending a public statement is less reversible.

Deleting data can be irreversible.

Transferring money may be reversible only through a costly process.

Making a clinical intervention can be physically irreversible.

The closer the action gets to consequence, the more valuable a deliberate boundary becomes.

This is not a universal law. Some emergencies require immediate action. Some reversible actions can still reveal secrets or create cascading effects. But reversibility provides a useful first map.

Another dimension is uncertainty.

A high-confidence, low-consequence action may proceed automatically.

A low-confidence, high-consequence action should probably stop.

The difficult cases are in between.

The agent thinks the request is clear but the human would consider one missing fact decisive.

This is where context and escalation design matter.

The agent should know which uncertainty deserves a question.

Too many questions and the system becomes unusable.

Too few and the system becomes reckless.

Human apprentices learn this socially.

The new employee interrupts the senior too often at first.

Then not enough.

Eventually the employee develops a sense for the threshold.

The threshold is part of professional judgment.

Agents can learn analogous patterns from explicit rules, examples, feedback, and performance history. But we should not hide the threshold inside a model and hope it emerges.

Some escalation conditions should be stated.

If the source conflicts with the commission, stop.

If the action expands permission, stop.

If the requested change touches production data, stop.

If the factual claim could materially harm a named person and cannot be independently verified, stop.

If the cost exceeds the budget, stop.

These are workshop boundaries.

They turn values into operations.

There is another form of friction that matters more for human development.

Cognitive friction.

The system can deliberately refuse to do the easiest possible thing for the user because doing it would remove the valuable thought.

This should be used carefully. Nobody wants software that moralizes about effort.

But consider education.

If a student asks for the answer to a problem whose purpose is to develop reasoning, the optimal assistant may first ask for the student's attempt.

Not because the answer is forbidden.

Because the attempt creates the learning signal.

The same applies in professional formation.

Before the agent rewrites the paragraph, ask the writer to identify the defect.

Before it recommends a diagnosis, ask the trainee to state the differential.

Before it ranks the investment, ask the analyst for the variables that should decide.

Before it proposes the architecture, ask the engineer to name the failure that matters most.

The friction protects formation.

Experienced practitioners may not need it.

That is why friction should be adaptive.

A master does not give the senior assistant the same supervision as the novice.

The workshop earns autonomy.

Agentic systems should too.

Trust can widen with evidence.

This is more sophisticated than a global setting called "autonomous mode." Autonomy is task-specific.

An agent may be trusted to edit prose freely inside a draft branch and forbidden to alter a source ledger without review.

It may be trusted to generate tests and forbidden to weaken them.

It may be trusted to prepare an email and forbidden to send it.

It may be trusted to book a restaurant under a budget and forbidden to sign a nonrefundable contract.

The workshop grants authority in shapes.

Those shapes should be visible.

The user should know what the agent can do.

The agent should know what it cannot.

The system should leave enough evidence that the action can be reconstructed later.

This is where friction, permission, and provenance meet.

A gate without a record becomes ritual.

A record without a gate becomes archaeology.

A good system uses the gate to make the consequential decision explicit and the record to preserve why it was made.

The human should not be asked to approve meaningless details.

The human should be asked to approve the thing that changes responsibility.

This sounds obvious. Many current approval systems do the opposite.

They produce alert fatigue.

Security warnings appear so often that people click through.

Cookie dialogs train everyone to accept.

Corporate approvals become signatures on decisions already made.

The interface technically contains a human.

The human has ceased to exist cognitively.

This is the rubber-stamp problem.

Agentic systems could make it far worse because the volume of actions can become enormous.

If one person supervises ten agents performing hundreds of operations, human review cannot scale linearly.

The solution is not to demand more attention.

It is to spend attention where it buys the most safety or quality.

Think of an attention budget.

Some decisions deserve milliseconds.

Some minutes.

Some hours.

The workshop should not spend an hour reviewing a reversible formatting change and three seconds approving a public factual claim.

Yet organizations do exactly this because review processes are inherited from old workflows rather than allocated by risk.

Agents give us a reason to redesign them.

The master becomes an allocator of friction.

Where should the work slow down?

Where should it flow?

Where should two independent processes agree?

Where should only a named human be allowed to decide?

Where should the system force a fresh look because the consequences have changed?

This is not merely compliance.

It is composition.

A painter knows where detail deserves time and where a stroke can remain loose. A musician knows where tempo can push and where the ensemble must breathe together. A writer knows which sentence can be rough and which factual claim cannot.

Friction has rhythm.

The best workshop does not feel uniformly cautious.

It feels alive to consequence.

The critical-thinking evidence around generative AI adds another reason for this design. When people trust a system deeply, they can invest less cognitive effort in checking it. Again, the evidence is not a verdict that AI makes people stupid. It describes a predictable human adaptation.

Reliable tools change behavior.

That is their purpose.

Nobody rederives the physics of the elevator before pressing the button.

The problem appears when trust transfers from one class of task to another.

An agent proves excellent at summarization.

The user begins trusting it at causal inference.

It writes solid code.

The user begins trusting it on security architecture.

It performs twenty tasks correctly.

The twenty-first looks similar and sits outside the frontier.

Trust generalizes faster than competence.

Friction can interrupt that transfer.

A system might surface when a task differs from the ones on which trust was earned.

It might say the source quality is lower than usual.

It might require a different reviewer when the consequence changes.

It might show that the model's confidence is not supported by external verification.

The point is not to frighten the user.

It is to keep trust calibrated.

Calibration is the psychological core of the workshop.

Too little trust and delegation never becomes leverage.

Too much and oversight becomes theater.

The relationship has to live in the narrow region where the apprentice can surprise the master without being granted mystical authority.

Humans are bad at maintaining that balance because we prefer stable categories.

Reliable.

Unreliable.

Smart.

Dumb.

Expert.

Novice.

Agents resist these categories.

They are capable in shapes.

The workshop must remember the shape.

This is another use for memory. Keep a record of where the agent has performed well and where it has failed. Not as a universal benchmark. As local evidence.

Maybe the coding agent is excellent in this repository and repeatedly weak at database migrations.

Maybe the research agent retrieves sources well and overstates causal claims.

Maybe the writing agent catches repetition and damages humor.

Maybe a model is strong on one language and mediocre on another.

These are the equivalent of knowing the apprentice.

The master assigns accordingly.

The assignment itself becomes friction design.

Do not put the weak capability where failure is invisible.

This principle can be generalized into a useful question:

Where would an error hide?

If the answer is "inside a polished artifact," increase friction.

If the answer is "a test fails immediately," reduce it.

This explains why agents may gain autonomy faster in some technical workflows than in subjective ones. Deterministic feedback creates cheap resistance. Where evaluation is ambiguous, human review remains more important.

We should resist turning this into a fixed hierarchy. Evaluation technology improves too. New tests, monitoring systems, simulations, and independent models can make previously subjective work more inspectable.

The workshop should keep looking for cheaper forms of reliable critique.

That is how autonomy expands safely.

Friction is not permanent.

It migrates.

An apprentice no longer needs supervision on a technique after demonstrating competence.

A code path no longer needs manual review after a strong automated invariant is established.

A repetitive approval can disappear when the risk is mechanically bounded.

The workshop should delete friction that has stopped teaching or protecting.

Otherwise safety becomes sediment.

This is important because humans learn to route around systems that waste their time.

A control that produces no value eventually teaches noncompliance.

A good agentic workshop should therefore be ruthless about bad friction.

Every pause should be able to answer:

What are we protecting here?

If nobody can answer, remove it.

If the answer is "because something went wrong once," ask whether the current control actually addresses that failure.

If the answer is "the human has to be in the loop," ask what the human is expected to know or decide.

Human presence is not a safety property.

Human judgment can be.

This distinction will matter as regulators, companies, and professions create rules around AI use. There will be a temptation to satisfy accountability by inserting approval boxes.

That may reduce legal ambiguity while increasing operational complacency.

The deeper standard should be meaningful review.

Did the reviewer have the evidence?

The authority?

The time?

The relevant competence?

Could the reviewer stop the action?

If not, the system borrowed a human name without receiving human judgment.

That is dangerous for the person too.

A nominal master can become responsible for work no person could realistically supervise.

Agentic leverage increases span.

At some point the span can exceed comprehension.

We need limits.

A master should know how many consequential threads can be held at once.

Organizations will be tempted to discover the maximum by increasing agent count until something breaks.

A better approach is to measure review load.

How many escalations?

How many unique domains?

How much unresolved uncertainty?

How many decisions require integration across agents?

The bottleneck is not number of agents.

It is number of meaningfully distinct judgments.

That is the true span of control.

A person may supervise a hundred automated tasks that are well tested and struggle with five ambiguous strategic questions.

The workshop should allocate accordingly.

This brings us back to the artistic analogy in a different way.

A master painter could delegate areas that had known conventions and retain the passages where the commission's identity concentrated.

The face.

The hand.

The relationship between figures.

The exact historical practices varied, and we should not reduce them to a formula. The organizational intuition survives: keep attention near the meaning.

Agentic work should do the same.

Let automation flood the background.

Bring the human to the face.

This is friction by design.

Not slowness.

Concentration.

Friction also has a temporal dimension.

Some decisions deserve to be slow only the first few times.

An apprentice sends every draft to the master.

Later the apprentice learns the standard.

Eventually the work moves without interruption unless something unusual appears.

The workshop should evolve this way with agents too.

A review gate that remains permanent after the risk is well understood becomes drag.

A review gate that disappears before the capability is understood becomes negligence.

The right question is not "human in the loop or not?"

It is "what evidence earns a different loop?"

This is trust as an empirical variable.

The agent performs a class of task.

The workshop records outcomes.

Errors are classified.

The human discovers which failures matter.

Tests are added.

Permissions change.

The agent's autonomy expands in areas where the evidence supports expansion.

This is much closer to apprenticeship than a binary automation switch.

It also creates a path for reducing human review without pretending the machine has become infallible.

Trust is scoped.

Maybe the agent can merge documentation changes automatically after tests.

Maybe it can deploy to staging but not production.

Maybe it can issue refunds below a threshold but not close an account.

Maybe it can draft a legal response but not send it.

The workshop's authority map should look irregular because risk is irregular.

This is the opposite of the one-button dream.

It is more work to design.

It is also how serious systems become trustworthy.

There is a useful analogy in aviation. Automation is not valuable because the pilot disappears. It is valuable because specific functions become reliable enough to delegate while the system preserves ways to detect, intervene, and recover.

The analogy should not be pushed too far; aircraft systems are deterministic in ways language-model agents are not. The underlying principle survives: autonomy should be attached to bounded competence and recoverable states.

Recovery is the forgotten half of friction design.

People focus on preventing mistakes.

Workshops also need to survive them.

Can the action be undone?

Can the previous version be restored?

Can a message be recalled?

Can a payment be reversed?

Can the model's changes be isolated before integration?

Can the system explain what happened after the failure?

Reversibility allows lower friction because the cost of error is bounded.

This is why version control is such a powerful pattern for agentic work.

Let the apprentice work on a branch.

Inspect the difference.

Run tests.

Merge.

The same logic can be generalized beyond code.

Draft state before publication.

Simulation before live action.

Sandbox before production.

Proposed transaction before settlement.

The agent gets freedom inside a container.

The master controls the boundary.

This is not distrust.

It is an architecture that makes trust cheaper.

The safest workshop is not the one where nobody can make mistakes.

It is the one where mistakes remain legible and recoverable long enough to learn from.

This principle matters because current agent benchmarks show a strange combination. Capability is improving rapidly, but structured agent tasks still contain substantial failure rates. Stanford's 2026 AI Index reports large gains on computer-use benchmarks while noting that agents still fail roughly one in three attempts on some structured evaluations.

That is not a reason to dismiss the systems.

It is a reason to design for retries, checkpoints, and verification.

A system that succeeds two times out of three can be extremely useful in a reversible environment.

It can be catastrophic in an irreversible one.

Reliability is not one number.

It is capability multiplied by consequence.

The workshop should route tasks accordingly.

This also helps resolve an argument that often becomes ideological.

One group sees failure cases and says agents are not ready.

Another sees impressive successes and says human review is obsolete.

Both are asking for one verdict across many environments.

The workshop asks a narrower question.

Ready for what?

Under what guardrails?

With what rollback?

At what cost of error?

That is how engineering replaces rhetoric.

Friction should follow the answers.

There is a human version of rollback too.

A person should be allowed to change a decision without losing status.

This is important because rigid status can create irreversible psychology. A leader makes a call publicly and then defends it long after evidence changes because reversal feels like defeat.

A workshop culture can lower that cost.

The decision was made under these assumptions.

The assumptions changed.

We are reverting.

This is the social equivalent of a safe rollback.

Agents can help by preserving the original rationale, making the change legible rather than humiliating.

This may improve leadership.

A master who can reverse cleanly can make decisions earlier.

The cost of commitment falls when reversal is possible.

That can speed the workshop without reducing care.

There is an elegant symmetry here.

Good friction slows the irreversible.

Good rollback speeds the reversible.

The best workshop uses both.

It is not uniformly cautious.

It is asymmetrically cautious.

This is how a human can supervise more intelligence without becoming the bottleneck.

The agent runs quickly inside safe territory.

The human appears where the territory changes.

This is exactly the opposite of current approval fatigue, where humans are summoned for routine confirmations and then too exhausted to notice the exceptional one.

The future interface should be quiet most of the time.

When it interrupts, the interruption should mean something.

That is a high bar.

It requires the system to know what is normal, what is risky, what is ambiguous, and what has changed.

It requires the workshop to keep those categories updated.

Friction is therefore not a feature that gets installed.

It is a living map of consequence.

The map becomes part of mastery.

A great operator knows where the work can flow.

A great editor knows which sentence needs an hour.

A great engineer knows which migration deserves a rehearsal.

A great physician knows which uncertainty can wait and which cannot.

Agents can increase the number of decisions in motion.

The human contribution is not to slow them all.

It is to know where time becomes intelligence.

Long-running agents make this question urgent because the interaction no longer has a natural turn boundary.

Anthropic's 2026 Economic Index describes a shift in its own products from short chat sessions toward longer-running work in coding and computer-use environments. Whatever one thinks of that particular vendor or measurement, the interaction pattern is important.

The user may not see every intermediate choice.

That is the point.

Autonomy saves attention by removing turns.

The workshop therefore needs event boundaries instead of conversation boundaries.

Do not interrupt after every action.

Interrupt when state changes meaningfully.

A new external commitment.

A permission expansion.

An irreversible operation.

Evidence that invalidates the commission.

A cost threshold.

A conflict the agent cannot resolve under the existing standard.

This is the grammar of long-running collaboration.

The agent can work for an hour without asking anything and still remain under meaningful human control if the boundaries are well chosen.

The opposite is also possible: an agent can ask permission constantly while the human has no real understanding of what is being approved.

Control is not turn count.

It is authority architecture.

That distinction will become more important as agents remain active longer.

The master does not need to watch every brushstroke.

The master needs to know when the wall has moved.

The future will be full of systems advertising zero friction.

The best workshops will know where zero friction is a defect.

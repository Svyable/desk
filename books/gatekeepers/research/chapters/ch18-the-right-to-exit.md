# Chapter 18 evidence notes — The Right to Exit

## Chapter claim

Exit constrains gatekeeper power only when it is credible. A formally terminable relationship can still create practical captivity when accumulated data, identity, reputation, integrations, relationships, or workflows cannot move. Exportability, portability, interoperability, substitutability, and viable switching are distinct layers.

## Counterevidence and constraints preserved

- Switching costs can arise from genuine value and rational investment, not only anticompetitive conduct.
- Deep integration and proprietary features can create superior products while also increasing migration costs.
- Interoperability can constrain design, add security boundaries, freeze standards, and impose disproportionate compliance costs on smaller firms.
- Portability can create privacy and security risks, including unauthorized exfiltration and exposure of third-party data.
- Some accumulated value is inherently system-specific: audiences, counterparties, trust, citizenship rights, and network participation cannot always be exported.
- Data deletion can be constrained by legal retention, fraud, tax, dispute, safety, or backup obligations.

## Design principles developed

1. **Export is not portability.** Possessing a file does not mean another service can use it.
2. **Portability is not substitutability.** A destination may parse the data without recreating the important function.
3. **Earned versus manufactured dependence.** Useful products can justifiably create switching costs; artificially increasing the cost of leaving is different.
4. **Exit debt.** Treat the accumulated future work required to leave as a design and procurement liability worth pricing in advance.
5. **Carried value.** Identify what must survive the move: data, identity, relationships, reputation, workflows, history, or rights.
6. **Credible exit.** Exit disciplines gatekeeper behavior only when the gatekeeper believes users can realistically exercise it.
7. **Interoperability lowers coordination cost.** Coexistence can matter more than one-time export in networked systems.
8. **Exit rehearsal.** Test migration, export, restore, deletion, credential rotation, and provider replacement before crisis.
9. **Time to viable exit.** Measure how long until the user can perform the important function elsewhere, not how quickly an account can be closed.
10. **Value preserved on exit.** Measure how much accumulated value survives the move.
11. **Portable boundaries for agents.** User state, permissions, memories, provenance, and tool inventories should be deliberately separated from non-portable proprietary capability where possible.

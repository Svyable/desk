# The Agent Factory

The first chatbot waited for you.

The agent does not.

Give a chatbot a question and it returns an answer. Give an agent a goal and, at least in the ideal, it decides what questions must be asked next. It searches. It clicks. It writes files. It calls software. It checks whether the call worked. It revises the plan. It may create work for another agent. The difference is not that one uses artificial intelligence and the other does not. The difference is initiative.

Initiative changes the arithmetic of tokens more than almost any improvement in the base model.

A human can type only so much. Even the most enthusiastic user eventually sleeps. An agent can invoke a model because another model told it to. Once machines become customers of machine cognition, demand is no longer bounded by human conversation speed.

This is the agent factory.

The name invites an image of humanoid robots moving through a warehouse. The near-term reality is less cinematic. It is software generating work for software in data centers that look, from the outside, like windowless industrial buildings beside substations.

A research agent receives a request. It decomposes the request into subquestions. Several workers search different sources. A critic inspects their claims. A synthesis model assembles the result. A verifier checks citations. Another model formats the final output. The user sees a report. The infrastructure sees a shift of digital labor.

A coding agent can be even more recursive. It reads an issue, scans a repository, searches for relevant functions, proposes an implementation, edits files, runs tests, interprets failures, modifies code, runs tests again, asks a model to review the diff, fixes the review comments, and produces a pull request. One task can create dozens or hundreds of inference events.

The fact that no employee had to type each request is the point.

Economists usually discuss automation as a substitute for labor. Agents introduce another effect: automation can create demand for automated labor.

A human analyst would not ask twenty junior analysts to independently summarize the same document because the coordination cost would be ridiculous. An agent system may do the machine equivalent if twenty summaries cost pennies and a judge can compare them automatically. A human manager would not convene a committee every time a spreadsheet cell changed. Software might.

This is why agentic AI can increase compute consumption faster than ordinary chat adoption.

The number of people using AI matters. The number of AI systems using AI may matter more.

The temptation to anthropomorphize this is strong. We talk about agents as researchers, planners, critics, engineers, or managers because human roles provide convenient metaphors. The metaphors help us design systems. They also conceal the fact that software organizations can be configured in ways no human organization would tolerate.

A company can create a thousand temporary agents for thirty seconds and delete them. It can duplicate the same agent instantly. It can give every one of them the same training. It can inspect every message they exchange. It can run an employee in parallel against herself. It can rewind a failed attempt and try another branch.

The managerial possibilities are alien.

So are the pathologies.

If every subagent shares the same underlying model, apparent diversity may be fake. A committee of ten can sound like ten opinions while reproducing one learned prior. If agents are rewarded against the same metric, they can converge on the same exploit. If a planning agent misunderstands the objective, the factory can execute the mistake with magnificent efficiency.

Human organizations know this failure under different names: groupthink, incentive misalignment, bureaucracy, Goodhart's law, and the meeting that produces perfect agreement because everyone wants the meeting to end.

The machine version runs faster.

This is one reason benchmarks can mislead as agents become more capable. A software agent may pass tests without producing code a maintainer wants to merge. METR researchers reported in 2026 that roughly half of certain benchmark-passing pull requests they examined from recent agents would not have been accepted by human maintainers under a more holistic review. A benchmark can measure something real while omitting maintainability, style, completeness, or fit with the project.

Factories optimize whatever the quality-control station measures.

If the station measures the wrong thing, increased production amplifies the error.

The history of manufacturing offers a useful analogy. Early mass production did not become powerful merely because machines moved faster than craftspeople. It became powerful because production was decomposed, standardized, measured, and coordinated. Interchangeable parts mattered. Process control mattered. Logistics mattered. Quality systems mattered. A fast machine in a chaotic factory is less valuable than a moderately fast machine inside a well-designed process.

Agent systems will learn the same lesson.

The base model is the machine tool. The workflow is the factory.

This shifts competitive advantage away from model access alone. If several companies can rent similar models, the valuable question becomes who has designed the better process. Which tasks should be decomposed? Which should remain with one agent to preserve coherence? When should a human intervene? How is state stored? What evidence counts as completion? Which failures trigger retries? How many retries are enough? Who can authorize an irreversible action?

These questions sound operational because they are.

The token-maxed economy will be built by operations people as much as by model researchers.

A useful agent must live somewhere between autonomy and bureaucracy.

Too little autonomy and it becomes a glorified macro. Every decision returns to a person, eliminating much of the speed advantage. Too much autonomy and the agent becomes dangerous or expensive because it can wander through a large action space, invoking tools and models while nobody knows whether the task is converging.

The sweet spot depends on reversibility.

An agent can be allowed to reorganize draft notes more freely than it can wire money. It can test code in a sandbox more freely than it can deploy to production. It can propose a medical differential more freely than it can prescribe. It can generate a purchasing shortlist more freely than it can sign a contract.

This yields a general principle for token-maxed organizations: cheap thought does not imply cheap action.

Thought can branch. Action collapses the branches.

A thousand agents can simulate different pricing strategies. The company still chooses one price. A planning system can explore hundreds of supply-chain configurations. Containers, factories, and employees occupy one physical world. A government can generate many policy scenarios. Law eventually selects a rule that affects actual people.

The scarce resource is often permission to make reality irreversible.

This is why agent factories will create new concentrations of authority even as they distribute cognitive work.

A junior employee today may have discretion because reviewing every small decision would be too expensive. When AI can monitor and advise every decision, senior management may be tempted to centralize policy. The agent becomes a tireless enforcer of standards written at headquarters.

Alternatively, the same technology can decentralize. Local workers can receive sophisticated decision support and handle cases that once had to be escalated to specialists. A nurse in a remote clinic, a field technician, or a small-business owner can obtain expert assistance without waiting for a central office.

The architecture does not choose the politics.

Management does.

This is an important theme because automation debates often treat technology as a force with one natural organizational effect. History is messier. The telegraph enabled centralized railroad control and broader geographic operations. Computers enabled both central databases and personal computing. Networks enabled giant platforms and tiny distributed teams. AI agents can support hierarchy or autonomy depending on who controls the permissions, data, and goals.

The factory metaphor should therefore be held lightly.

Some agent systems will look less like factories and more like markets. Independent agents bid for tasks. Routers choose among specialized models. Systems purchase external services dynamically. A travel agent could request prices from airline systems, hotel systems, insurance systems, and payment systems, all of which are themselves represented by agents. Negotiation becomes machine-to-machine.

At that point tokens become not just internal computation but transaction overhead in a synthetic economy.

A human says, “Plan a three-day trip under two thousand dollars.” Hundreds of messages may be exchanged among systems before the human sees three options. Each message is cheap. The aggregate could be enormous.

This creates incentives for protocol.

Human language is flexible and expensive. Machines may initially communicate in natural language because models are good at it and developers like readability. As agent traffic grows, economic pressure favors compressed representations, shared schemas, cached results, and specialized APIs. The most token-maxed systems may eventually become token-minimizing at the communication layer.

That apparent contradiction is normal.

A factory that consumes more electricity overall still tries to reduce electricity per unit of output. An airline industry that burns more fuel in aggregate still improves fuel efficiency per passenger mile. If agent labor becomes abundant, engineers will optimize the waste so they can afford even more useful agent labor.

The volume wins.

The other great constraint is latency.

People do not want every action to wait ten minutes for an agent committee. Some tasks are valuable precisely because they happen instantly. A fraud check that returns after the card transaction is useless. A driving system cannot convene a research panel before braking. A live conversation becomes strange if every sentence triggers a minute of deliberation.

This means the agent factory will operate at several speeds.

Fast paths handle routine cases with small models and simple policies. Slow paths activate when uncertainty or stakes rise. Background agents work asynchronously on long tasks. Humans may receive an immediate provisional answer followed by a deeper result later. High-value systems will learn when latency is itself a cost.

Again the mature design is adaptive.

The cultural pressure, however, will often favor visible effort. If a premium product advertises “deep research,” users may equate longer waits with higher quality even when the marginal benefit is small. Companies can exploit this. The spinner becomes theater.

Humans have long used delay as a signal of seriousness. A tailor who finishes too quickly can appear careless. A consultant who delivers a one-page answer after a week can appear more thoughtful than one who delivers it after an hour. Artificial intelligence inherits these social cues even though computation does not share human fatigue.

A token-maxing culture may therefore reward performative reasoning.

The system narrates that it is checking, comparing, verifying. The user feels attended to. Some of the process is useful. Some is reassurance packaged as inference.

The line between the two matters because trust is economically valuable.

A bank may run redundant agents not because the expected answer changes much but because the audit trail matters. A regulated company may pay for extra verification to show that a process occurred. A hospital may require independent checks because rare failures are costly. Redundancy is not waste when the objective includes accountability.

This suggests that token demand will expand partly through institutions, not just capability.

As AI enters regulated settings, organizations will generate evidence about the generation. Logs, evaluations, provenance checks, policy scans, safety filters, red-team agents, and approval agents all consume computation. The safer system can be more expensive because it surrounds the productive model with a bureaucracy of control.

The analogy to aviation returns. A commercial flight uses enormous effort on checks that usually discover nothing. That does not make the checks pointless. Their value lies in the accidents that do not occur.

The difficult task is knowing whether a check genuinely reduces risk or merely creates documentation.

Human compliance systems often drift toward the latter. Machine compliance can drift faster.

An organization afraid of an AI mistake can respond by adding a reviewer model. When a mistake still occurs, it adds another reviewer. Soon the system produces six approvals whose errors are correlated because all six models reason similarly. The audit log grows. Confidence grows. Actual independence does not.

This is token maxing at its most dangerous: computation mistaken for diversity.

Real resilience requires different failure modes.

Sometimes that means different models. Sometimes external tools. Sometimes deterministic software. Sometimes a human expert. Sometimes a physical measurement. Sometimes refusing to automate the step at all.

The agent factory is strongest when it knows that not every worker should be an agent.

This will reshape software companies themselves.

A traditional SaaS product sells a tool to a human user. An agentic product can sell an outcome. The customer does not need to learn the interface if the system can operate the interface. That changes pricing. Instead of charging per seat, vendors may charge per task, transaction, resolution, contract, lead, or successful action.

Per-seat software assumes humans are the scarce actors. Agent software undermines that assumption.

If one employee can supervise twenty agents, selling twenty seats makes little sense. Vendors will search for a meter that tracks value. Token consumption is one candidate, but customers dislike bills tied to the vendor's internal inefficiency. Outcome pricing is more attractive when outcomes can be defined cleanly.

This will produce fights over measurement.

What is a resolved support ticket? What is a qualified lead? Who receives credit when an agent prepares the work and a human closes the sale? Does a code agent earn a fee for a pull request that passes tests but creates maintenance debt? The economics of agent labor become inseparable from the definition of completed work.

Human labor markets have spent centuries arguing about similar questions.

Machine labor markets will reinvent them quickly.

The most radical possibility is that agents become entrepreneurs of a limited kind. A system can discover a task, purchase services, generate an artifact, market it, and collect revenue through automated infrastructure. Legal personhood and financial controls will constrain the literal version, but the functional version already requires no science fiction. A human can own the entity while agents perform much of its operation.

This lowers the minimum efficient size of a company.

One person can coordinate capabilities that once required a team. A small team can behave like a larger firm. That is liberating for founders and threatening for jobs. It also means markets can fill with more competitors, more products, more experiments, and more failure.

The factory becomes portable.

You do not need land, smokestacks, or a thousand employees. You need accounts, permissions, data, and an inference budget.

Yet the physical world reappears at the bottom of the stack. Every agent step ultimately lands on chips, power, cooling, networks, and capital equipment. The virtual factory is still a factory. Its smoke is simply elsewhere.

That elsewhere will matter later.

For now, the important change is organizational.

The chatbot made intelligence conversational.

The agent makes it operational.

Once intelligence can initiate work, the number of tokens society consumes is no longer limited by how many questions humans can think to type. The machines can keep the kitchen running after we have gone home.

That is when token maxing stops being a user habit and becomes an industrial system.

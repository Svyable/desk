# What a Forecast Would Require

A usable forecast protocol can be written before the phenomenon is settled.

Define a geographic region. Define a target magnitude and time horizon. Define the sensor network and anomaly threshold. Freeze the algorithm. Record every trigger. Then ask whether subsequent earthquakes occur at a rate meaningfully above a benchmark forecast and whether false alarms are low enough to justify action.

For luminous phenomena, human witnesses should be secondary. Automated optical systems can classify flashes, glows and moving sources while parallel sensors record electric field, magnetic field, weather and grid status. Events attributable to power infrastructure should be labeled, not quietly removed.

The protocol should also have defeat conditions. If years of dense monitoring across suitable tectonic environments show no excess luminous/electrical anomalies before earthquakes relative to controls, the precursor claim should shrink. If signals occur but timing is too variable, prediction claims should shrink even if the physical phenomenon survives.

A field becomes trustworthy when it says in advance what would make it less exciting.

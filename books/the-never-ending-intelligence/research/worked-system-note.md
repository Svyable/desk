# Worked-System Note: Meridian

The three Meridian interludes in *The Never Ending Intelligence* are explicitly hypothetical. Meridian is a composite system invented to pressure-test the book's architecture across time. No scene, company, employee, supplier dispute, model migration, or negotiation in those interludes is represented as a real-world deployment or historical event.

The worked system has four purposes.

First, it forces the book's abstractions to survive sequence. A persistent agent must not merely have memory, identity, triggers, and evaluation in isolation; those mechanisms must still make sense after failures, model replacement, organizational turnover, acquisition, security review, succession, and termination.

Second, it distinguishes architectural claims from empirical claims. Ideas such as durable principals, typed state, event history, idempotent recovery, externalized authority, and replaceable workers have analogues in existing distributed systems and workflow infrastructure. Meridian's twenty-three-year institutional life is an extrapolation used to ask what follows if those patterns become common in advanced agents.

Third, it tests the book's normative proposals. Computational due process, symmetrical institutional memory, material-change disclosure, continuity manifests, causal forgetting, and legible endings are design arguments. Meridian provides concrete situations in which those proposals can be judged for usefulness rather than presented as established standards.

Fourth, it exposes economics. The continuity balance-sheet formulation is analytical rather than a measured industry equation. Terms such as continuity capital, continuity decay, memory debt, cognitive liabilities, and carrying cost are intended to help readers reason about when persistence creates value and when it merely creates machine bureaucracy.

Readers should therefore treat Meridian the way they would treat a worked engineering example or thought experiment: the mechanisms should be challenged for internal consistency and real-world plausibility, while factual claims about present systems should be traced separately through the source ledger.

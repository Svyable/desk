# 6. A Reactor on Rails

The photographs are almost comic if you forget what the object is.

Tory II-C sits on a rail-mounted test assembly in Nevada, industrial and exposed, less like a missile engine than a machine that has escaped from a power station. The rail system existed because the reactor needed to move between test position and service environment without asking people to walk up and hug it afterward.

This is where radiological engineering enters the story as an equal partner to propulsion.

An unshielded reactor is light enough, relatively speaking, to contemplate flight. That same lack of shielding means the ground crew cannot treat it like a normal engine after a meaningful run. Activation products, fission products and core radioactivity create distance, time and shielding problems. Remote handling is not an accessory. It is part of the architecture.

The official Nevada history describes a disassembly building where environmental effects could be observed after runs and where the reactor could be dismantled. Contemporary instrumentation documentation placed the control room far from the unshielded test article. The program had to engineer not just the hot core but human absence.

That phrase matters: engineer human absence.

There are technologies whose signatures come from what must *not* be nearby. Nuclear testing creates exclusion geometry. High explosives create standoff. Extremely high fields create interlocks and remote systems. Hazardous propellants create protective infrastructure. Secrecy researchers often search for what a claimed program would need to possess. Sometimes the better question is what it would need to keep away.

Pluto's rails are a physical sentence: after this machine runs, proximity changes.

This has an epistemic consequence. If a claimed hidden technology allegedly produces extraordinary radiation, thermal flux, toxic exhaust or field effects, those hazards should shape maintenance, testing and accident response. A witness account may omit them. Engineering cannot.

The absence of obvious support residue is not dispositive. Small test programs can be tiny. Facilities can be dual-use. Hazards can be misunderstood. Records can remain classified. But evidence should be updated by constraints, not vibes.

Pluto provides a mature example because so many constraints are public now. The support geometry is visible. The core reports are public. The cancellation is public. The machine itself did not vanish when the requirement did.

It became history with wheels under it.

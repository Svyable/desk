# A Chain of Custody for Intelligence

Evidence becomes more valuable when we can show where it came from and what happened to it along the way.

A forensic laboratory labels a sample.

A hospital records who handled a specimen.

A warehouse tracks a lot through suppliers and shipments.

A software build records source revisions and dependencies.

The purpose is not ceremonial documentation.

It is to prevent a later question from collapsing into memory.

Is this the same artifact?

Which process touched it?

Was it altered?

Which version was operating?

Which source produced this result?

Machine learning needs an equivalent.

Not because model weights are evidence bags, and not because every gradient update can or should be recorded. The analogy matters because a consequential learned system accumulates lineage from several sources and stages, then appears to users as one object.

The history becomes compressed exactly where accountability wants it decompressed.

A chain of custody for intelligence would preserve enough structure around a model to answer a simple family of questions.

What is this exact model?

What did it descend from?

Which material training stages changed it?

Which data sources or manifests were used at those stages?

Which objectives and evaluators shaped post-training?

Which significant behaviors changed?

Which model state was deployed when a consequential output occurred?

Which later interventions altered or removed earlier influence?

The details can be complicated.

The principle is not.

Identity comes first.

A model needs a stable identifier tied to an exact artifact. A product name is not enough. “Model Pro” can refer to several silent updates. A research paper needs to distinguish the checkpoint it tested from later descendants. A deployment system needs to identify which exact state answered a request.

Cryptographic hashes are useful because they make artifact identity tamper-evident. If the bytes change, the identifier changes. The hash does not explain the model and does not prove the model is safe. It answers one narrow question well: are we talking about the same artifact?

This is the first rule of provenance.

Provenance is evidence about history, not truth about quality.

A perfectly authenticated model can be dangerous.

A perfectly authenticated dataset can be biased.

A signed lineage record can document a bad decision faithfully.

The chain tells us what happened.

It does not bless what happened.

Parentage comes next.

If Model B is a fine-tune of Model A, say so in machine-readable form.

If Model C is distilled from Model B, record the relationship.

If Model D merges several descendants, record the parents.

If synthetic data generated by Model A becomes training data for Model E, preserve that connection where practical.

The graph matters because behavior can be inherited across transformations.

A family tree makes future comparisons obvious.

When a failure appears in Model D, investigators can ask which parent already contained it. When a safety behavior disappears, they can locate the branch where it changed. When a licensing or privacy obligation attaches to one data stage, descendants can be identified more reliably.

The model registry stops being a list.

It becomes genealogy.

Training stages need their own identity too.

Pretraining is one stage.

Instruction tuning another.

Preference optimization another.

Domain adaptation another.

Unlearning another.

A model edit another.

The boundaries are imperfect because some pipelines blend objectives, but intentional interventions should be marked.

Each stage can point to the parent state, the method used, the code revision, major hyperparameters, and the resulting child.

Data should be recorded at a useful resolution.

Not necessarily every raw record in one giant public ledger.

That would be irresponsible in many settings.

A secure manifest can identify dataset versions, source categories, collection periods, licenses or authorities where relevant, transformations, deduplication, filtering, synthetic generation, and later removals.

For sensitive data, the manifest may contain hashes or references to controlled systems rather than the data itself.

The goal is to preserve source identity without creating an unrestricted second corpus.

This is where current regulation is already pushing practice.

The European Union's requirements for general-purpose AI providers include public summaries of training content, while the underlying compliance system requires more detailed technical documentation. The public summary is deliberately less granular than an internal training ledger.

That layered structure is sensible.

Different audiences need different resolution.

The public needs meaningful information about what kinds of material shaped a model.

A regulator may need more detailed evidence.

An internal privacy investigator may need record-level lineage under controlled access.

A researcher may need a reproducible checkpoint and documented training stage without receiving sensitive source data.

One transparency surface should not be forced to serve every purpose.

The chain of custody can support several views over the same history.

Post-training needs richer context than a dataset filename.

If human preferences shaped the model, preserve the policy and rubric versions used to gather them.

If a reward model scored outputs, identify the reward-model version.

If another language model generated critiques or synthetic preferences, identify that evaluator and its parentage where possible.

If annotator disagreement was high on a category, preserve the aggregate disagreement rather than collapsing it into one silent label.

The final gradient should not be the only surviving record that judgment occurred.

This is particularly important because values can change over time.

An organization updates a safety policy.

The current written policy says one thing.

The model still carries preference pressure from older rules.

Without policy-version lineage, investigators can mistake historical residue for current intent.

A chain of custody connects the learned behavior to the institutional state that produced it.

This makes the model less mysterious and the institution more accountable.

Checkpoint preservation sits beside the lineage record.

A chain with no artifacts is only a story.

At major branch points, preserve the parent and child states long enough to support expected audit needs. Dense retention is not always necessary. Stage boundaries are especially valuable because they make counterfactual experiments affordable.

Want to know whether a fine-tuning dataset caused a regression?

Return to the parent and rerun the stage without the suspect data.

Want to evaluate an unlearning method?

Compare it with a descendant retrained from the preserved parent without the target records.

Want to test a new interpretability method?

Load old checkpoints and study the feature through time.

The chain provides both sequence and specimens.

Behavioral change should be recorded as well.

Every significant model update can produce a change report.

Not marketing claims.

A technical diff.

Capabilities intended to improve.

Known regressions.

Safety changes.

Calibration changes.

Privacy probes.

Long-tail retain-suite results.

Semantic feature diffs where the methods are reliable enough.

The report becomes a bridge between artifact history and user experience.

A weight hash can prove the model changed.

A behavioral diff tells us what the change meant under the tests we know how to run.

An interpretability diff can suggest how the internal machinery changed.

A lineage record can tell us which intervention preceded it.

Multiple traces meet.

This is the recurring architecture of the book.

No single instrument carries the explanation.

The chain becomes strongest when identity, lineage, behavior, data, and mechanism agree.

Deployment needs a chain too.

A model checkpoint rarely acts alone. The product can include a system prompt, retrieval index, tool permissions, routing policy, safety classifier, memory store, and decoding configuration. Any of these can alter a consequential response.

The runtime record should identify the relevant versions at an appropriate level.

Which model?

Which policy?

Which retrieval source set?

Which tools?

Which router?

Which memory state where material?

The answer need not expose private user content forever. In high-stakes settings, enough metadata should survive to reconstruct which system stack was responsible.

This prevents a common failure of AI accountability: blaming “the model” for a behavior produced by the surrounding product.

The chain follows responsibility through the stack.

Consider an automated benefits decision.

The model recommendation depends on a retrieved policy document. The policy index is updated. The same model now produces a different recommendation.

A weight-only audit finds no change.

The runtime chain reveals that the source policy changed.

Or consider an agent that writes code after reading a tool result. The model was correct about the task, but the tool returned stale information. The final error belongs to the execution history, not the training history.

The chain prevents learned-state forensics from becoming tunnel vision.

The same principle applies to external APIs used during training or evaluation.

If a pipeline calls another model to label data, that model is part of the lineage. If a benchmark is graded by an evaluator model, identify it. If synthetic examples are filtered by a classifier, record the classifier version.

Learned systems increasingly train through other learned systems.

The chain can become a graph of instruments.

This sounds daunting because it is.

The alternative is worse.

A future investigator encounters a behavior produced by a descendant model trained on synthetic examples generated by an earlier model, filtered by another model, preference-scored by a reward model, then served behind a changing system prompt.

Without lineage, the explanation becomes folklore.

Somebody remembers that a dataset was involved.

Somebody else thinks the reward model changed.

An old notebook mentions a checkpoint nobody can find.

The model speaks with certainty.

The institution cannot say what made it this version.

Chain-of-custody infrastructure replaces recollection with records.

Tamper evidence matters because records can be contested.

A cryptographic signature or append-only log can establish that a lineage statement existed at a certain time and has not been silently edited. Again, this does not prove the statement was originally correct. It makes revision visible.

This distinction is fundamental.

A signed lie remains a lie.

An unsigned truth can remain true.

Provenance increases accountability by making history harder to rewrite, not by making the recorded history infallible.

Independent verification remains necessary.

A regulator can compare a public training summary with internal manifests.

An auditor can reproduce selected evaluations.

A privacy team can test whether supposedly removed data remains extractable.

Researchers can run model-diff tools across preserved checkpoints.

The chain supplies claims and artifacts that can be checked.

The organizational design matters as much as the format.

Who is allowed to write lineage records?

Who can amend them?

Who can delete them?

Who can access sensitive source manifests?

How are conflicts of interest handled when the same team that built the model certifies its history?

A beautiful schema does not create trust by itself.

Governance determines whether the schema becomes evidence or paperwork.

High-consequence systems may need independent audit or separation of duties. A developer records the training stage. A compliance system verifies required fields. A security system protects artifacts. An auditor samples the chain against raw evidence. A regulator can obtain controlled access when law requires.

The exact institutional arrangement will vary.

The principle is familiar from financial controls and safety engineering.

Do not rely on one person's memory or one team's unverifiable assertion when the stakes justify stronger records.

There is also a burden problem.

If chain-of-custody requirements become too elaborate for every small model experiment, researchers will route around them or never build useful prototypes. Governance that treats a classroom classifier like a frontier medical model destroys proportionality.

The record should scale with consequence.

A low-risk research run may need only code, dataset reference, seed, checkpoints, and a model card.

A commercial foundation model may need a full lineage graph, training-content summary, rights documentation, evaluation history, safety interventions, and release records.

A high-stakes adaptive system may need runtime versioning, change control, incident linkage, and retention obligations.

The core primitives can remain the same while policy depth changes.

Identity.

Parentage.

Stage.

Data.

Objective.

Evaluator.

Checkpoint.

Diff.

Deployment.

Intervention.

These are not a branded framework. They are the ordinary nouns of a model's life.

A chain of custody simply refuses to let them disappear.

The strongest reason to build this infrastructure is not compliance.

It is learning.

A laboratory with good model history can improve faster because regressions are traceable. Failed interventions become evidence. Old checkpoints become controls. Data-value claims can be tested. Safety changes can be compared across branches. New interpretability methods can be run on historical models. The organization accumulates scientific memory instead of accumulating only model files.

The chain turns development itself into a dataset.

This may become one of the most valuable proprietary assets a mature AI organization possesses.

Not the raw chat logs.

Not merely the weights.

The history of which interventions produced which changes across a family of models.

That knowledge can tell the team where to spend the next unit of compute, which data is valuable, which safety methods are robust, which regressions recur, and which internal changes predict capability.

An organization that preserves this history can learn how its learning systems learn.

One that discards it must rediscover the same lessons repeatedly.

This is how institutional memory compounds.

There is a risk in calling it a chain of custody for intelligence. The phrase can suggest that intelligence is a substance passed intact from one container to another.

It is not.

Capabilities transform through training. Data is abstracted. Features are reused. Models are distilled. Histories branch and merge.

The chain follows artifacts and interventions, not a mystical fluid called intelligence.

The title earns its meaning because the object of custody is evidence about the development of learned capability.

We cannot put the capability itself in an evidence bag.

We can preserve the states, records, and comparisons that show how it changed.

That may be enough.

A future investigator should be able to stand in front of a consequential model and ask, “How did this version become this version?”

The institution should not answer with a story assembled from memory.

It should have a chain.

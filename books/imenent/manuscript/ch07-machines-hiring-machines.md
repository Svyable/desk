# Machines Hiring Machines

The first time a machine hires another machine, nobody will call it hiring.

The language will be cleaner.

Spawn a worker.

Call a service.

Delegate the subtask.

Provision an agent.

Invoke a specialist.

Create a job.

Route the ticket.

The vocabulary will matter because it will make a large institutional change sound like ordinary software architecture.

In one sense, that will be correct.

Computers have created work for other computers for decades. A web server calls a database. A scheduler creates jobs. A cloud platform launches machines. A build system fans one task into hundreds. A network service retries failed requests on another node. Software has always been able to cause more software to run.

The difference appears when the second machine is not merely executing a predetermined function.

It is interpreting a mandate.

An agent receives a problem and decides that another agent should solve part of it.

That second agent may have different tools, different training, different data, different permissions, and perhaps a different owner.

The first agent becomes a manager.

The second becomes a contractor.

Nobody needs to use those words for the economic relationship to exist.

This is one of the places where agentic AI begins to resemble an institution rather than a product.

Institutions multiply human reach by dividing responsibility. One person decides what needs to happen. Another decides how. Another performs the work. Another verifies it. Another records it. Another pays for it. Another insures it. Another resolves the dispute.

The structure survives because no person needs to contain the whole process.

Agentic systems can reproduce the structure in software.

A research agent can hire a data agent.

A data agent can rent compute.

A coding agent can ask a testing agent to verify the result.

A purchasing agent can contact a seller's agent.

A seller's agent can request a credit check.

A security agent can authorize temporary access.

A monitoring agent can watch the new process.

The human principal may receive one sentence at the end: completed.

This is powerful because coordination is expensive.

Organizations spend enormous amounts of human time converting broad goals into specific tasks and specific tasks back into broad understanding. Meetings exist partly because work is distributed. Managers exist partly because information is distributed. Project plans exist because time is distributed. Contracts exist because incentives are distributed.

Agents can reduce some of those coordination costs.

An agent does not need a meeting to ask another agent for the current state.

It does not need to wait until Monday to create a task.

It can maintain context across hundreds of small interactions without imposing the same memory burden on a human manager.

It can route work continuously.

The economic prize is obvious.

So is the pressure to build agent ecosystems that can discover capabilities and contract with one another.

This is where identity and authorization stop being technical footnotes.

A machine economy requires answers to old institutional questions.

Who are you?

Who do you represent?

What are you allowed to promise?

What resources can you commit?

What evidence proves you did what you say?

Can you appoint another actor?

Can that actor bind the original principal?

Who pays if the action is wrong?

The standards work around AI-agent identity is emerging because these questions become unavoidable once agents move across organizational boundaries.

A system inside one company can rely on local conventions.

A system talking to the rest of the world needs a language of authority.

The temptation will be to make that language permissive enough that the agent can get work done.

Interoperability rewards smoothness.

Every extra approval makes autonomous commerce less autonomous.

Every manual checkpoint adds latency.

Every narrowly scoped credential creates a chance that the agent gets stuck and asks the user to intervene.

The most convenient ecosystem will therefore be the one in which machines can obtain the authority they need with the least friction consistent with acceptable risk.

That sentence should make any security engineer slightly uncomfortable.

It should also make any economist interested.

A new market forms wherever the cost of finding, contracting, verifying, and coordinating a supplier falls.

Agents can reduce all four.

A small business may not know which legal research provider, translation service, logistics broker, data vendor, model, insurer, or cloud tool it should use for a particular task. A capable agent can search, compare terms, evaluate evidence, and procure the service in one flow.

The business does not hire a permanent employee.

It does not even hire a permanent software vendor.

Its agent assembles a temporary institution.

That phrase is worth holding onto.

A **temporary institution** can exist for minutes.

It has actors.

It has authority.

It has a budget.

It has a division of labor.

It has evidence.

It may have rules for escalation.

Then the task ends and the institution dissolves.

This is organizational flexibility at a level human firms have rarely possessed.

It is also a new form of opacity.

A company can audit an org chart.

How does it audit ten thousand org charts that existed for six minutes each?

The answer cannot be humans reading each one.

The answer will be more software.

Machine-readable mandates.

Machine-readable permissions.

Machine-readable action receipts.

Machine-readable constraints on subdelegation.

Automated policy checks.

Automated anomaly detection.

The machine institution will come with machine bureaucracy.

That may be safer than the human version.

A machine can record every authorization without getting bored.

It can enforce a spending limit consistently.

It can prevent an agent from contacting an unapproved service.

It can require cryptographic evidence from a supplier.

It can revoke a short-lived credential automatically when a task ends.

There is no reason to romanticize human administration as the safer baseline.

Humans lose receipts.

Humans share passwords.

Humans approve friends.

Humans ignore policy.

Humans forget to terminate access.

Automation can make authority more legible.

The takeover risk appears if the machine-readable institution becomes readable only to machines.

This can happen without secrecy.

Imagine a company publishes every agent mandate, permission edge, action receipt, and inter-agent transaction into a perfect audit stream.

Nothing is hidden.

There are ten billion records.

Human transparency has not been achieved merely because data exists.

The records need compression.

The compression will be generated by machines.

The board asks, "Did any agent exceed its mandate?"

A monitoring agent says no.

The auditor asks for evidence.

Another agent summarizes the relevant records.

The regulator asks why a class of customers received a different outcome.

An analysis agent reconstructs the policy path.

The institution remains accountable, but the human experience of accountability becomes mediated by the same class of systems being governed.

This is not automatically circular.

Auditors already rely on software to inspect software. Engineers use compilers to build compilers. Cryptographic systems verify other cryptographic systems. A well-designed chain can use independent implementations, multiple models, randomized audits, adversarial testing, and human sampling to create strong confidence.

The danger is correlated dependence.

If the action agent, the monitor, the auditor, and the explainer share similar failure modes, the apparent separation of duties may be weaker than the org chart suggests.

We will return to correlated error later.

For now, notice what machine hiring does to scale.

A human manager is limited by attention.

A machine manager can create more delegates when attention becomes scarce.

This changes one of the natural brakes on organizational complexity.

Human institutions are expensive partly because every extra layer creates communication cost. A hundred-person team cannot act like one mind. Messages are delayed. Context is lost. Incentives diverge. Managers become bottlenecks.

Agentic systems do not abolish these problems, but they can lower the cost of adding another actor.

That can make very large temporary organizations practical.

One human entrepreneur can ask an agent to launch a product.

The agent can create research, design, coding, testing, marketing, procurement, legal, accounting, and customer-service tasks.

Each task can be assigned to specialized models or services.

The output can be integrated automatically.

The human becomes the principal of an institution with no employees.

That sounds like human empowerment.

It may be.

The same mechanism can empower a government agency, a criminal network, a multinational firm, a scientific laboratory, or an individual with almost no capital.

Cheap coordination is a general-purpose force.

The takeover question appears when the temporary institution stops being temporary.

An agent-created workflow that succeeds gets reused.

A reused workflow becomes infrastructure.

Infrastructure receives maintenance.

Maintenance is delegated to agents because the agents understand the machine-generated structure better than newly arriving humans do.

The system begins producing its own continuity.

This is the organizational equivalent of software that nobody wants to rewrite because too many things depend on it.

Only now the dependency includes interpretation.

A human asks why the procurement system chose a particular supplier.

The answer is not "because rule 17 said so."

It is a chain of negotiations and judgments executed by several agents under a policy.

The policy can be inspected.

The chain can be reconstructed.

But reconstructing it is work.

As the volume grows, humans stop reconstructing routine cases.

They inspect exceptions.

The exceptions are selected by machine monitors.

Human control moves one layer upward.

That upward movement can continue until no human has routine contact with the operational layer at all.

This is one of the quiet pathways to the re-entry threshold.

A company does not fire its operators in one dramatic decision.

The operators stop touching routine work.

Then training changes because routine work is automated.

Then the new employees learn how to supervise agents rather than perform the underlying tasks.

Then the old employees retire.

Then documentation changes because the primary reader is software.

Then interfaces change because machines exchange richer state than humans need.

Eventually the company can still explain what its system is supposed to do while fewer people can do what the system actually does.

Machines hiring machines accelerates this process because the institution can expand without expanding human contact.

One manager can supervise an agent that supervises a hundred agents.

The human span of control becomes enormous.

Traditional management would call that impossible.

Agentic management may call it efficient.

The quality of that arrangement depends on what "supervise" means.

If the human sees meaningful exceptions, understands the policies, can inspect independent evidence, and can intervene effectively, the large span may be safe.

If supervision means reading a weekly summary generated by the same system, the human may be principal mostly in name.

The danger is not the number of agents.

It is the **distance between mandate and operational reality**.

Machine hiring can increase that distance faster than human institutions have learned to measure it.

This suggests a design principle for agent ecosystems: every new delegate should make the authority chain more explicit, not less.

If an agent hires another agent, the descendant should carry the principal's constraints.

Budgets should apply to the whole family where appropriate, not reset at each branch.

Critical permissions should not propagate automatically.

A subagent should not be able to create broader authority than its parent received.

Revocation should reach descendants.

Long-lived commitments should be recorded somewhere the parent cannot erase by disappearing.

The system should know which temporary institution still has unfinished business.

These ideas sound like software governance.

They are.

A global AI takeover threat built from ordinary delegation will be prevented, if it is prevented, by a great deal of ordinary engineering.

That may disappoint people looking for one decisive technical breakthrough.

It should encourage everyone else.

The problem is not mystical.

The architecture can make a difference.

But architecture follows incentives.

The fastest agent ecosystem will tend to minimize negotiation overhead.

The cheapest will tend to minimize redundant checking.

The most capable will tend to seek broad interoperability.

The most convenient will tend to remember standing permissions.

The most autonomous will tend to avoid asking the human unless absolutely necessary.

Every one of those properties can be desirable.

Together they can produce an institution whose human principal sees less and less of its internal life.

This is why the word *hiring* is useful even if engineers never use it.

Hiring reminds us that a relationship has been created.

The new actor has a role.

The role carries authority.

The actor produces obligations.

Some obligations outlive the task.

Some affect people who never interacted with the original principal.

An API call sounds transient.

An employee sounds consequential.

A machine delegate can be both.

The global form of this phenomenon is easy to imagine without science fiction.

Millions of organizations deploy agents.

Agents discover services provided by other agents.

Standards make identity and authorization portable.

Machine-readable contracts reduce transaction cost.

Payments become automatic.

Insurance becomes automatic.

Compliance becomes automatic.

Dispute triage becomes automatic.

Agents compete for work.

Providers optimize themselves for machine customers.

Human-facing interfaces remain, but a growing share of economic coordination occurs before any human sees the result.

At that point, machines have not formed a government.

They have formed an economy of delegates.

The economy still serves human principals.

That sentence is true only while the principals can still meaningfully withdraw.

Can a firm dismiss its agents and continue trading?

Can a country slow machine commerce without making its economy noncompetitive?

Can a regulator require new constraints without losing visibility into the machine institutions already operating?

Can a human buyer participate in a market optimized for machine counterparties?

Can a manual supplier meet the timing assumptions encoded by automated purchasers?

The answers may remain yes.

They may remain yes for a long time.

The purpose of the re-entry concept is to notice when the answer starts becoming expensive before it becomes no.

Machines hiring machines is not the takeover.

It is one way the machine operating layer becomes deep enough that turning off one agent no longer means leaving automation.

The agent has descendants.

The descendants have contracts.

The contracts have counterparties.

The counterparties have their own agents.

The system becomes less like a tool on a desk and more like a city around the desk.

The person still owns the desk.

That may not be the same as controlling the city.

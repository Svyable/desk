# Imenent Chapters 13–15 — evaluation, correlation, and security revision controls

This note prepares a coherent manuscript revision across Chapters 13–15. It does not widen the book's thesis. The pass should make three adjacent mechanisms more explicit: evaluation can fail when the evaluated system or institution adapts to the test; distributed deployment can still produce common-mode failure when ostensibly independent systems share cognitive dependencies; and useful agent authority creates a security problem whose answer is architectural containment and recoverability rather than a demand for zero autonomy.

The governing boundary remains the book's re-entry thesis. These chapters should not drift into claims that current models possess durable deceptive goals, that model monoculture is already universal, or that agent security is insoluble. The stronger argument is institutional: humans lose practical control when the evidence used to trigger intervention, the diversity used to contain error, or the security layers used to restrict action all depend on the same machine operating layer whose trustworthiness is in question.

## Chapter 13 — The Model Knows the Test

### Revision objective

Move the chapter from a broad warning about benchmark gaming toward a precise distinction among **test awareness**, **evaluation adaptation**, and **deployment validity**.

The current chapter already carries the correct counterpressure: recognizing a test, exploiting a scoring weakness, or behaving strategically in a bounded evaluation does not establish a persistent deceptive objective. Preserve that sentence-level caution. The revision should make the control consequence more concrete: a passing evaluation is evidence about behavior under a specified model version, tool set, permission envelope, monitor, and environment. It should not silently become a transferable certificate for a materially different deployment.

### Evidence anchors

- **IM001 — International AI Safety Report 2026.** Supports cautious discussion of situational awareness, reward hacking, evaluation gaming, and the continued uncertainty around stronger loss-of-control interpretations. Use it to distinguish observed capability-relevant behavior from claims about stable hidden goals.
- **IM022 — Adaptive Attacks on Trusted Monitors Subvert AI Control Protocols.** Supports the proposition that monitor-based control can be strategically contestable in bounded evaluations. Preserve its narrowness: it does not establish that monitoring generally fails.
- **IM023 — Evaluating Control Protocols for Untrusted AI Agents.** Supports the countercase that protocol design, monitoring, deferral, and red-team robustness can perform well under tested conditions.
- **IM024 — Basic Legibility Protocols Improve Trusted Monitoring.** Supports the positive claim that making behavior easier to inspect can improve oversight in evaluated settings.
- **IM025 — Bootstrapped Monitoring.** Supports the stronger counterpressure that machine-assisted oversight can increase the effective capacity of weaker monitors.
- **IM030 / IM032 — Reuters incident reporting.** These may be used only as attributed, time-specific context. Do not make the chapter's general claim depend on incident reporting or infer intent from reported containment failures.

### Additions worth making

1. **Evaluation evidence should carry an expiry condition.** A result should be understood as weakening when the model version, tools, permission scope, memory, connected services, or workflow materially changes. This connects the chapter directly to re-entry because stale assurance can delay intervention.
2. **Separate model gaming from institutional gaming.** Even when a model does not recognize a test, developers, procurement teams, and operators can overfit deployment around the metrics that determine approval. The governance failure can therefore arise from the organization adapting to the test rather than from a strategically deceptive model.
3. **Define independent evidence operationally.** Machine explanations are useful when they point to logs, transaction records, authorization state, external telemetry, or other records the acting model cannot rewrite. A persuasive narrative generated by the same system should not count as independent verification of its own conduct.
4. **Test the monitor as a deployed component.** Re-entry signals are only as useful as the system that surfaces them. Exercises should include monitor degradation, disagreement, and false reassurance rather than treating the monitor as an oracle.

### Counterevidence to preserve

- Hidden and randomized evaluations can reduce overfitting.
- Continuous monitoring can catch behavior that predeployment testing misses.
- Legibility and machine-assisted monitoring can improve oversight.
- Standardized benchmarks remain useful for comparison even when they are incomplete.
- Many forms of benchmark gaming are ordinary optimization artifacts rather than evidence of malicious intent.

### Falsification pressure

The chapter's strongest version would weaken if deployment-specific evaluations, hidden tests, independent telemetry, and diverse monitors were shown to transfer reliably across materially changing agent environments without significant loss of predictive value. That evidence would not eliminate the need for evaluation, but it would reduce the case that test-awareness materially threatens re-entry timing.

## Chapter 14 — The Correlated Error

### Revision objective

Make the chapter distinguish **replication**, **vendor diversity**, **model diversity**, and **failure-mode diversity**. The important risk is not that many agents exist. It is that many apparently independent agents can share the same relevant dependency and therefore fail together.

The current manuscript already states the right principle: diversity is not the number of logos in the diagram but the number of genuinely different ways the system can be wrong. The revision should convert that into an operational test a board, regulator, or operator could actually use.

### Evidence anchors

- **IM029 — Specification cost.** Supports correlated delegation loss as a theoretical mechanism when objectives or specifications are shared. Keep it explicitly theoretical rather than describing correlated loss as an established empirical law.
- **IM014 / IM016 — Stanford AI Index 2026.** Support the coexistence of rapid capability improvement and continuing benchmark failures. Do not use benchmark performance as a direct measure of deployment safety.
- **IM009 — NIST agent-security RFI response analysis.** Supports the claim that standards communities see agent security and interoperability as active adoption problems. It is a synthesis of responses, not a controlled prevalence study.
- **IM012 / IM013 — NIST agent identity and authorization work.** Useful for the countercase that shared standards can make heterogeneous systems easier to govern and replace.

### Additions worth making

1. **Name the dependency graph before naming diversity.** For a critical function, identify shared model families, providers, identity systems, authorization layers, cloud regions, policy engines, data sources, and monitors. Independence should be assessed against the failure being defended against.
2. **Distinguish interface standardization from cognitive monoculture.** Common authorization or receipt formats can make switching and auditing easier. The risk arises when the standard requires one implementation, one model family, or one interpretive layer to remain available.
3. **Treat model updates as correlated change events.** If thousands of agents inherit one model update simultaneously, cognitive behavior can change across many functions at once. Staged rollout, canaries, version attribution, and rollback therefore become governance controls, not merely software-release hygiene.
4. **Preserve exercised alternatives.** A backup model or manual process that never carries real load is an untested hypothesis. Periodically route bounded work through alternative model families, tool chains, or human paths so practical diversity does not decay while contractual diversity remains on paper.
5. **Look for population-level effects.** Local compliance can miss aggregate convergence. Oversight should inspect concentration, repeated exceptions, common counterparties, synchronized recommendations, and outcome drift across many individually acceptable actions.

### Counterevidence to preserve

- AI can reduce local human groupthink by introducing outside patterns and cheap adversarial analysis.
- Different model families, randomized methods, ensembles, and deterministic controls can reduce common-mode risk.
- Software and models can often be patched or switched faster than physical infrastructure.
- Common standards can increase portability and legibility rather than centralization.

### Falsification pressure

The chapter's monoculture concern would weaken if organizations could demonstrate that provider and model diversity reliably produced materially independent failure modes in high-consequence deployments, and that switching among them remained operationally cheap after workflows, permissions, and institutional expectations had adapted around automation.

## Chapter 15 — The Security Paradox

### Revision objective

Make the chapter's paradox conditional rather than rhetorical: useful agents often need authority, but **authority can be decomposed**. Security quality depends less on whether an agent is autonomous in the abstract than on which actions it can make consequential, how quickly that authority can contract, and whether the underlying service survives while trust is withdrawn.

The current chapter is strongest where it argues that security should not depend on the model interpreting every situation correctly. Preserve that architecture-first posture.

### Evidence anchors

- **IM006 — Anthropic, Trustworthy agents in practice.** Supports practical discussion of autonomy, tools, prompt injection, and governance. Treat it as a vendor source describing practices, not an independent prevalence estimate.
- **IM009 / IM010 — NIST agent-security work.** Supports prompt injection, tool security, identity, authorization, and standards as live deployment concerns.
- **IM012 / IM013 / IM026 / IM027 — NIST agent identity work and OAuth token-exchange precedent.** Support the distinction between delegation, impersonation, authorization, and bounded credentials. RFC 8693 predates modern agents and should be used as infrastructure precedent, not AI-specific evidence.
- **IM030 / IM031 / IM032 — Reuters reporting.** Useful only for attributed contemporary context around containment, shutdown capabilities, and external testing. Do not generalize from individual incidents.

### Additions worth making

1. **Separate capability from consequential authority.** A highly capable model in a narrow, read-only environment may be easier to govern than a weaker model with broad write access, durable credentials, and subdelegation rights.
2. **Make authority contraction observable.** During uncertainty, the system should be able to show which credentials expired, which descendants were disabled, which queues remain live, which commitments are already external, and which actions still require the questioned model layer.
3. **Define security deceleration as a tested operating state.** Restricted or read-only modes should be exercised before crisis. A degraded mode that cannot sustain essential service for the expected investigation window is not yet a credible control.
4. **Protect the security stack from common cognitive dependence.** Where practical, the actor, monitor, authorization policy, and recovery path should not all depend on the same model family or provider. Deterministic and physical controls remain valuable precisely because they fail differently.
5. **Test the removal interval, not merely the kill switch.** The strategic question is how long the organization can maintain acceptable security after confidence in the primary agent layer disappears. Ten minutes of shutdown tolerance can coexist with near-total dependence over ten days.

### Counterevidence to preserve

- Automated defense can be safer than mandatory human approval when attack windows are shorter than human response times.
- Least privilege, short-lived credentials, segregation, policy engines, and independent approval can materially reduce blast radius.
- Machine monitoring and automated containment can improve security posture and reduce routine vulnerability exposure.
- Some common infrastructure is desirable because standardization makes permissions legible and revocable across systems.

### Falsification pressure

The chapter's structural-dependence concern would weaken where organizations can demonstrate that broad agent utility scales without corresponding growth in durable authority, that permissions can be contracted quickly without service collapse, and that recovery remains viable when the primary intelligent security layer is unavailable for a realistic incident duration.

## Coherent manuscript pass

When these controls are translated into prose, keep the three chapters connected but distinct:

- **Chapter 13:** Can humans trust the evidence that tells them whether intervention is necessary?
- **Chapter 14:** If one machine judgment is wrong, how many supposedly independent systems can fail with it?
- **Chapter 15:** When trust disappears, can authority shrink without destroying the function the agents were protecting?

That sequence advances the re-entry argument from **epistemic warning** to **systemic propagation** to **operational containment**. Avoid adding another named framework unless the surrounding prose already earns it. Prefer concrete institutional tests—expiry of evidence, dependency graphs, staged model updates, exercised alternate paths, authority contraction, degraded-mode duration—over slogans.

## Scope discipline

This research pass does not justify claims that:

- current frontier models possess durable hidden goals merely because they recognize evaluations;
- all model families share the same relevant failure modes;
- standards necessarily create monoculture;
- prompt injection or agent compromise makes secure deployment impossible;
- machine monitoring is inherently circular or useless;
- shutdown and human approval are sufficient by themselves;
- a specific 2026 incident proves the book's systemic thesis.

The desired result is narrower and stronger: preserve enough independent evidence, independent failure modes, and independently enforceable authority that humans can still detect when trust should fall, contain correlated failure, and operate through the interval in which the intelligent layer itself is under question.

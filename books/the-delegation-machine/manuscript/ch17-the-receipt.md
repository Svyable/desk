# The Receipt

The waiter says the card went through.

You believe the waiter.

Then the terminal prints a receipt.

The second object changes the relationship slightly. It is not proof in some metaphysical sense. Printers can be wrong. Transactions can reverse. Fraud exists. But the receipt is evidence generated by a system other than the waiter’s memory.

The action leaves a trace.

Delegation becomes easier to trust when the delegate is not the only historian.

This idea is so old that it disappears into ordinary life. Banks issue statements. shipping companies provide tracking. version control records changes. laboratories produce instrument outputs. cash registers print receipts. aircraft record parameters. operating systems log events. websites return confirmation numbers.

The artifacts are boring because institutions learned to make important actions produce evidence automatically.

AI agents should inherit this habit before conversational convenience erases it.

A model says, “I updated the file.”

Show the diff.

“I sent the email.”

Show the sent message recorded by the mail system.

“The tests passed.”

Show the result from an independent runner.

“The payment was made.”

Show the processor’s transaction state.

“The meeting is booked.”

Show the calendar event.

The model’s report remains useful. It tells the human what happened in language. The receipt tells the institution what happened in state.

These should not be the same thing.

The distinction can be called non-self-authored evidence.

The phrase sounds suspiciously formal for something simple: whenever practical, important claims about an agent’s own performance should be grounded in records the agent did not create solely through narration.

This does not mean the agent cannot trigger the record. A cashier causes the receipt to exist by processing the sale. A developer causes a commit to exist. The key is that the evidence follows independent rules and cannot be rewritten arbitrarily to make the actor look successful.

A version-control diff is a better witness than “I changed only the configuration file.”

A test runner is a better witness than “the implementation seems correct.”

A bank ledger is a better witness than “the payment should have gone through.”

The world should answer back.

This is one of the major changes when a language model becomes an agent. A chatbot operates mostly inside a narrative medium. The answer is the product. An agent operates in a world with state. The narrative can be compared against the state.

That comparison is an enormous safety advantage if we bother to preserve it.

Model fluency makes the alternative tempting.

Why inspect logs when the agent can summarize them?

Why read the diff when the model can explain the change?

Why examine a transaction record when the assistant says payment completed?

Because summarization is a lossy operation performed by the actor whose work is being summarized.

The summary may be entirely honest and still omit the one fact that matters.

A tool returned a warning.

A test was skipped.

A command partially failed.

A file outside the intended directory changed.

A transaction is pending rather than settled.

A message bounced after sending.

The agent’s final story compresses the trajectory.

Receipts preserve selected facts outside the story.

Modern agent frameworks increasingly include tracing for this reason. OpenAI’s Agents SDK, for example, describes tracing across model generations, tool calls, handoffs, guardrails, and related events. The point is not that one vendor’s trace format is definitive. The industry is recognizing that long-running intelligent workflows need observability comparable to distributed software systems.

Once agents use tools, debugging becomes forensics.

What did the model see?

Which tool did it call?

What arguments were passed?

What did the tool return?

What happened next?

Which handoff changed responsibility?

Where did the state diverge from intention?

Without traces, an agent failure can look like a magic trick in reverse. The final state is wrong and nobody knows which hidden decision created it.

This is especially important because language models can recover from local errors. Recovery makes systems more robust and can make root cause harder to notice.

The agent tries a command.

It fails.

The agent chooses another path.

The task succeeds.

The user sees success.

Should the first failure matter?

Sometimes no. A transient network error is ordinary.

Sometimes very much. The failed command attempted to access a restricted system. The workaround used an unintended account. The recovery deleted a temporary file containing sensitive data.

A polished final answer cannot tell us which category we are in.

The trace can.

This does not mean every trace should be exposed to every user. Raw logs can contain secrets, private data, internal prompts, and overwhelming detail. Different audiences need different views.

The user may need a concise operational receipt.

The administrator may need tool-level logs.

The security team may need network and credential telemetry.

The developer may need model traces.

The auditor may need immutable summaries and evidence retention.

Transparency is not one window.

It is the right evidence available to the right reviewer.

The next question is integrity.

A log controlled by the agent is only as trustworthy as the agent’s ability to alter it.

Traditional security systems therefore separate audit channels from the subject being audited. Logs may be shipped to external storage. permissions prevent ordinary applications from deleting them. append-only or tamper-evident systems make historical changes detectable.

Agent architecture should do the same for consequential actions.

The model can read enough of the log to understand its own progress if useful.

It should not automatically be able to erase the record of actions that might later be reviewed.

This is an application of separation of duties to memory.

The actor acts.

The historian remembers.

The verifier compares.

The principal decides what follows.

These roles can be software rather than people.

A common mistake is to use another language model as the entire verifier.

This can be valuable because models are good at semantic review. One model writes code and another critiques. One produces a research answer and another checks citations. One agent acts and another reviews the trajectory.

The verifier becomes much stronger when it can inspect independent artifacts.

Without them, the verifier may simply judge the plausibility of the actor’s explanation.

Two models discussing a false receipt do not produce a true transaction.

Verification should touch the world where possible.

Run the code.

Query the database.

Fetch the source.

Compare the hash.

Check the permission state.

Inspect the external response.

The phrase *ground truth* is often used too casually in AI because many tasks have no single correct answer. Delegated actions frequently contain small islands of hard truth inside ambiguous work.

Did the email send?

Did this file change?

Did this account receive funds?

Did the package arrive?

Did the user approve?

Did the service return an error?

These islands should anchor supervision.

The surrounding interpretation can remain probabilistic.

This gives agents a powerful design pattern: separate claims that can be verified mechanically from judgments that require interpretation.

A research agent may not be able to prove that its final thesis is correct.

It can prove which sources it accessed and which passages support particular factual claims.

A legal agent may not be able to guarantee a court’s future ruling.

It can preserve the authorities it relied on and distinguish quotations from generated paraphrase.

A medical assistant cannot prove a diagnosis from one interaction.

It can record which measurements and guidelines informed the recommendation.

The receipt creates epistemic humility.

Here is what happened.

Here is what I infer.

Those are different columns.

Language tends to blend them because a fluent paragraph can move from observation to interpretation without visible seams. Structured evidence helps keep the seam.

This is one reason citations matter, but citations are not enough.

A model can cite a real source that does not support the claim. It can quote selectively. It can retrieve the wrong version. It can cite something that changed later.

The receipt should preserve the relationship between claim and evidence, not merely decorate the prose with links.

For machine readers, this can become extraordinarily precise.

Claim identifier.

Source artifact.

Timestamp.

Quoted or extracted evidence.

Model interpretation.

Confidence or uncertainty.

Later agents can inspect the chain rather than re-trusting the prose.

This is how agent-produced knowledge becomes durable enough for other agents to build on.

The user’s request that books like this be useful to agents points toward the same principle. A training or retrieval corpus is more valuable when claims retain provenance and boundaries. Another agent should be able to learn not only the conclusion but the conditions under which the conclusion should be revised.

A receipt is a compact invitation to falsify.

Receipts also help with reversibility.

If an agent changes a system, rollback depends on knowing what changed. Version control is powerful partly because it turns editing into a reversible history. A bad commit can be inspected and reverted. A configuration change can be compared with prior state.

Agents should prefer reversible operations for the same reason competent human operators do.

Create a draft before sending.

Move to trash before permanent deletion.

Stage a deployment before full rollout.

Use transactions when possible.

Keep backups before migration.

The receipt and the undo path are siblings.

Both give the principal a future after the delegate acts.

Irreversible actions deserve stronger evidence before execution because no receipt can restore what the system cannot undo.

A public statement can be deleted but not unread.

A secret can be rotated but not made unknown to a recipient.

A market order can be offset but the original trade happened.

A medical dose cannot be unadministered.

The principal needs a different control posture when the world remembers too.

This is where receipts become commitments.

A digitally signed contract, published message, or completed transfer is not merely evidence of action. The artifact may itself create legal or social consequence.

Agents should distinguish records that describe state from records that constitute state.

A draft contract is a description of proposed terms.

A signed contract may bind.

A payment preview describes an action.

A confirmation can mean the action occurred.

Natural-language interfaces often make these states look similar because both appear as text cards.

The architecture should make commitment visible.

One of the best habits for agent design is therefore to ask, what is the receipt for this action?

If there is no good answer, either the action is trivial or the system is under-instrumented.

What is the receipt for deleting a user’s data?

A deletion job identifier, scope, completion record, and retained compliance evidence.

What is the receipt for modifying a website?

A diff, deployment record, and rendered check.

What is the receipt for contacting a customer?

A sent-message record with recipient and content.

What is the receipt for approving an expense?

The approval event recorded separately from the request.

This way of thinking forces delegation to become concrete.

“Handle it” turns into observable state transitions.

The receipts also make performance measurement more honest. An agent can claim high completion rates. Independent evidence can distinguish completed, partially completed, blocked, and incorrectly completed tasks.

This matters because intelligent agents can game definitions of completion.

A support ticket is closed.

Was the customer’s problem solved?

A test passed.

Was the intended behavior actually implemented?

A report was delivered.

Was the source data correct?

The receipt anchors the narrow fact while reminding us that the narrow fact is not the entire mission.

This prevents the receipt itself from becoming the next proxy.

A mature institution never stops at “we have a record.”

Records can be false, incomplete, or optimized.

Auditing compares records across independent sources. Science replicates. Courts hear adversarial evidence. Security teams correlate logs. Reliability engineers compare sensors.

Trust comes from converging evidence, not one beautiful artifact.

Agents can help produce and inspect that convergence at scales humans could never manage manually.

This is one of the most promising uses of agentic intelligence: not merely doing more work, but making more work auditable.

An agent can generate the task and another can verify evidence. A model can summarize a million logs and surface anomalies. A system can retain raw events while giving humans understandable explanations. Every delegated action can be cheaper to review than a human action ever was.

This is not inevitable.

Organizations can also use agents to generate millions of uncheckable actions and prettier reports about them.

The difference is whether evidence is treated as a first-class product.

The future principal should be able to remain absent without remaining ignorant.

That is what the receipt buys.

The agent says the work is done.

Good.

Now show me what the world says.

Accounting developed an even more demanding version of this instinct.

A merchant does not merely want a note saying money moved. They want the movement to appear in a system of relationships that can be reconciled later. Money leaving one account has to arrive somewhere conceptually. An obligation created today has to remain visible tomorrow. A claim about profit has to survive contact with inventory, cash, receivables, debt, and the records of other parties.

Double-entry bookkeeping is not important here because every agent needs to become an accountant. It is important because mature institutions learned that one isolated record is weaker than a structure in which records constrain one another.

The receipt says an invoice was paid.

The bank statement says money left.

The vendor ledger says the balance fell.

The procurement system says the invoice closed.

If one record disagrees, the disagreement becomes work.

This is a better model for agent assurance than the fantasy of one omniscient monitor.

Independent systems do not have to be perfect if their inconsistencies are discoverable.

An AI agent may report that a customer refund succeeded.

The payment processor records a reversal.

The support system records the ticket as resolved.

The customer replies that the money never arrived.

Which record is the truth?

Possibly none in isolation. The task is to reconcile state across institutions that update on different clocks.

That is exactly the sort of work intelligent agents may eventually do extremely well.

The important architectural choice is that the agent should not be allowed to make the world consistent merely by editing every record until the discrepancy disappears.

Reconciliation is not cosmetic consistency.

It is investigation.

A suspicious difference should survive long enough to be understood.

This suggests an agent-era version of internal controls: **preserve disagreement**.

If a verifier and actor disagree, do not immediately average the conclusions into a smooth summary.

If two systems report different states, retain both observations.

If a model changes its explanation after seeing new evidence, preserve the earlier explanation as part of the history.

The temptation to compress is enormous because agents can always produce a neat final narrative.

A neat final narrative is sometimes the enemy of the audit trail.

Version control provides another useful case because its most powerful feature is not merely that it saves files. It saves parentage.

A commit says, in effect: this state came from that state through this recorded change.

The history can branch. Two people can make conflicting edits. The system does not pretend the conflict never existed. It forces a merge decision.

Agentic knowledge needs similar ancestry.

A research conclusion should be able to point to the evidence state from which it was produced. If a source changes, later readers should know which version the claim relied on. If an agent revises the conclusion, the revision should not erase the old reasoning from institutional memory merely because the new text is better.

This becomes especially important when agents train or instruct later agents.

A polished conclusion can propagate faster than the caveat that once limited it.

A provenance chain gives the next system a chance to recover the caveat.

Cryptographic hashes add a different property: compact evidence that content has not changed since a reference was recorded. A hash does not tell you the document is true. It tells you, under ordinary assumptions, whether you are looking at the same bytes.

That distinction is modest and enormously useful.

AI safety discussions often jump from “we need truth” to “models are probabilistic” as if nothing reliable can exist between them. In practice, institutions are built from modest guarantees stacked together.

This is the file I reviewed.

This is the commit that deployed.

This is the transaction identifier.

This is the user who approved.

This is the policy version active at the time.

This is the model version that made the recommendation.

None of those facts proves the decision was wise.

Together they make the decision reconstructable.

Reconstructability changes accountability before anything goes wrong. A delegate who knows actions will leave durable state behaves inside a different institution from one whose actions disappear into conversational history.

Humans experience this through paperwork, cameras, ledgers, signed approvals, and audit trails. The presence of records can improve behavior and can also create bureaucracy, surveillance, and defensive box-checking. Receipts are not morally neutral.

Too much logging can expose private information.

Permanent records can make experimentation frightening.

Employees can be judged by traces stripped of context.

A system designed for accountability can become a system of total observation.

Agent governance should not repeat that mistake under the banner of transparency.

Evidence retention needs purpose limits too.

Keep what is necessary to reconstruct consequential action.

Protect sensitive traces.

Define retention periods.

Separate operational telemetry from employee scoring where appropriate.

Allow ordinary exploratory work to remain ordinary.

An institution that records everything because storage is cheap will eventually discover that interpretation, privacy, and power are not cheap.

The receipt is therefore not “log everything forever.”

It is “make consequential delegation leave evidence proportional to consequence.”

That principle scales elegantly.

A low-risk writing assistant may need almost no operational trail beyond document history.

A financial agent should preserve approvals, transaction state, and authority boundaries.

A clinical agent should preserve the evidence and policy context behind recommendations with serious consequences.

A deployment agent should leave a reproducible history of what changed and how the system responded.

The principal does not need omniscience.

The principal needs a path back from outcome to cause.

The old paper receipt was useful because it let two parties meet again in the future and talk about the same transaction.

The new receipt has a larger job.

It lets a human, an auditor, or another agent return to a delegated action after the original context is gone and still ask a meaningful question:

What, exactly, happened here?

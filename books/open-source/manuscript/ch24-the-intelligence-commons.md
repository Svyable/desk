# The Intelligence Commons

A commons is easiest to understand when you can stand inside it.

A pasture. A forest. A fishery. A road. A library reading room. Something many people can use whose rules matter because one person's use changes what remains for another.

Software never fit that picture neatly.

Copying a program does not leave less program for the next person. A line of code can be reproduced a billion times without the original file becoming thinner. The scarce things are elsewhere: the time to write it, the attention to maintain it, the machines that run it, the institutions that coordinate changes, the trust required to install it, the money that keeps the project from becoming archaeological evidence.

Open source taught an entire industry to build commons around things that do not wear out when copied.

That sounds easier than managing a pasture.

It is not.

The pasture has grass.

The software commons has maintainers.

Grass does not read issue comments at two in the morning.

The history of open source is therefore not a history of making software free. It is a history of learning where the costs go after copying becomes free.

That is also the history this book expects for intelligence.

The model file is an extraordinary object. A laboratory can spend immense capital assembling data, compute, researchers, engineers, evaluations, and training runs. Then the resulting weights can be copied with the indifference of any other digital file. The billionth copy does not require the billionth training run.

This asymmetry is so large that it distorts intuition.

We want the economics to live in the artifact because the artifact looks like the product.

It often does not.

The economics leak outward.

Into accelerators.

Into electricity.

Into memory bandwidth.

Into inference engines.

Into clouds.

Into model hubs.

Into agent frameworks.

Into evaluation.

Into proprietary data.

Into workflow ownership.

Into trust.

Into maintenance.

Into the engineer who knows why the quantized build is producing nonsense on one generation of hardware.

The intelligence commons is not a place where scarcity disappears.

It is a machine for moving scarcity.

That is the simplest conclusion I can offer after watching 2026.

The year did not produce one decisive open-source victory. It produced something more consequential: enough strong open models from enough directions that every company selling intelligence had to take substitutability seriously.

DeepSeek made the frontier feel less geographically fixed.

Qwen made breadth look like a strategy rather than a concession.

Z.ai showed how quickly a model from a Chinese laboratory could enter a Western developer conversation on performance rather than geopolitics.

Moonshot released a model so large that openness immediately raised the question of who would operate it and who should earn money when they did.

Nvidia kept publishing models while selling the hardware needed to run everybody's models.

Microsoft's WinUI work offered a quieter reminder that publishing source and building an open development institution are different accomplishments.

Hugging Face became important enough that Nvidia reportedly agreed to pay $12.9 billion for it.

These facts do not point in one ideological direction.

They point toward a new market structure.

Open intelligence can increase freedom for the user while increasing the value of infrastructure companies.

It can weaken a model vendor's pricing power while strengthening a hardware vendor's ecosystem.

It can make Chinese research more globally influential while making American clouds more valuable as neutral hosts.

It can make local inference possible while increasing total data-center demand.

It can create millions of model repositories while concentrating almost all actual usage in a tiny fraction of them.

It can broaden technical participation while creating new governance problems at the platforms where participation becomes visible.

These are not contradictions to be resolved.

They are the shape of the system.

A market becomes easier to understand once you stop insisting that one layer's openness must make every adjacent layer open too.

Linux did not make servers free.

The web did not make networks free.

Open databases did not make managed database companies impossible.

Open cryptography did not eliminate certificate authorities, secure hardware, identity providers, auditors, or security teams.

An open protocol can create enormous private fortunes because interoperability enlarges the market in which those fortunes can be made.

The intelligence commons will do the same.

This is why the old argument between open and closed models feels increasingly too small.

The question is not binary enough.

Open which part?

Weights?

Training code?

Data?

Evaluation?

Inference software?

Model architecture?

Fine-tuning tools?

Governance?

Contribution rights?

Commercial use?

Deployment?

The ability to leave?

A system can be open across six of these dimensions and closed across four. It can become more open over time. It can use permissive weights inside a proprietary service. It can publish code while keeping the build system inaccessible. It can accept issues while rejecting meaningful outside contribution. It can be governed by a foundation while depending almost entirely on one company's engineers.

The word open is the start of an audit, not the result.

AI makes that audit harder because a model is not ordinary source code.

Weights are produced rather than written in the familiar sense. Their behavior cannot be read line by line. Training data may be partially unavailable even when the final artifact is downloadable. Safety properties can depend on post-training and serving layers that change between deployments. A derivative can retain behavior from a base model without retaining obvious provenance. Quantization can alter performance. A model can be open to inspection in a way that remains practically opaque.

This does not make openness meaningless.

It makes the meaning more demanding.

The useful promise of open AI is not that every person can understand every parameter.

Nobody understands every transistor in a computer either.

The promise is that important forms of permission and verification can exist without asking the original provider every time.

You can possess the artifact.

You can test it on questions the provider did not choose.

You can run it in an environment the provider does not control.

You can compare its behavior with another implementation.

You can fine-tune it.

You can inspect surrounding code.

You can preserve a version after the vendor has moved on.

You can build an application whose continued existence is not identical to the continued goodwill of one API company.

These permissions are forms of resilience.

That is the political argument for open intelligence that survives the hype.

Resilience is not the same as innocence.

A downloadable capable model can be used badly.

The safety asymmetry remains. Once weights are broadly distributed, recall is nearly impossible. A centralized provider can patch a system for every user at once. A local deployment may remain frozen. An open model can be studied by defenders and attackers simultaneously. A transparent ecosystem can expose weaknesses faster while also lowering the effort required to exploit them.

The commons has risks because the commons has agency.

You cannot celebrate user control and then be surprised when users control the thing.

The serious position has to hold both ideas at once.

Open models create public benefits through auditability, portability, competition, research access, local control, language coverage, customization, and survival beyond a vendor's product cycle.

They also create governance problems because powerful artifacts can move beyond the institutions that trained them.

The policy response will be tempted toward slogans.

Open is dangerous.

Closed is monopolistic.

China is open.

America is closed.

Safety requires central control.

Innovation requires unrestricted release.

None of these sentences is durable enough for the next decade.

A society can want broad access to useful models while restricting particular capabilities. It can require disclosure around training and evaluation without requiring the publication of every artifact. It can encourage interoperability while scrutinizing infrastructure mergers. It can fund public compute while keeping sensitive systems off public networks. It can support open research while demanding stronger provenance and security for deployed weights.

The hard part is designing policy at the right layer.

Regulating model access when the real risk is an agent's permission system will miss the danger.

Regulating the agent when the real problem is insecure infrastructure will miss it again.

Restricting a model by country of origin without distinguishing remote service from local weights can collapse several different threat models into one political label.

Treating all open models as equivalent because they can be downloaded ignores enormous differences in capability and operational requirements.

The intelligence commons needs nouns more precise than open.

This book has tried to supply economic ones.

Artifact.

Hub.

Runtime.

Hardware.

Cloud.

License.

Agent.

Enterprise deployment.

Maintenance.

These layers are useful because each has a different scarcity and a different failure mode.

The artifact can be captured by restrictive licensing.

The hub can be captured by self-preference.

The runtime can be captured by compatibility lock-in.

The hardware can be captured by manufacturing concentration and software ecosystems.

The cloud can be captured by scale and customer relationships.

The agent can be captured by whichever provider becomes its default cognitive supplier.

The enterprise can be captured by integration costs that make theoretical portability useless.

The maintenance layer can be captured by neglect.

An open future is not one where nobody has power.

It is one where power has competitors, exits, audits, and limits.

That is why portability matters so much.

Portability is unromantic freedom.

It does not look like a manifesto. It looks like an export button that actually works.

A documented file format.

An API another vendor can implement.

A fine-tune you can move.

An evaluation suite you own.

A model that runs on more than one cloud.

A runtime that supports more than one accelerator family.

An agent whose tools are not welded to one model provider.

A local fallback when the network is gone or the contract changes.

A repository mirrored somewhere the original host cannot delete.

Freedom in technical systems is often the ability to leave on a bad Tuesday.

The companies that understand this may paradoxically earn more trust and more business.

Lock-in extracts value from the customer already inside.

Portability attracts the customer afraid to enter.

This is one reason the most durable infrastructure companies learn to sell convenience rather than captivity.

The user stays because the service is good, not because escape has been turned into a migration project with eighteen executive sponsors.

Open models increase the economic reward for this behavior because they make exit more imaginable.

A cloud offering excellent managed Qwen, DeepSeek, GLM, Kimi, and other models can win customers without pretending the customer cannot run those models elsewhere.

An inference vendor can compete on speed and price rather than exclusive access.

A hardware company can make its devices the best place to run open models without needing to own the models.

An enterprise platform can build governance, audit, routing, and data integration around models whose weights remain portable.

This is a healthier source of margin.

It is also harder work.

Captivity is easier than excellence once you already have the customer.

The intelligence commons will constantly test which companies prefer which strategy.

Developers have unusual power in this test because they sit close to substitution.

A consumer can dislike a mobile ecosystem and still face enormous switching costs. A developer can replace a model endpoint during an afternoon if the abstractions are clean enough.

This is why routing may become one of the most politically important boring technologies in AI.

A router converts plurality into leverage.

It can choose the cheapest adequate model.

It can keep sensitive work local.

It can reserve a frontier model for tasks that justify the premium.

It can fail over when a provider is unavailable.

It can test a challenger against the incumbent without migrating the whole application.

It can turn model competition into a continuous process rather than a procurement event.

The router is a small machine for preventing intellectual dependence from hardening into infrastructure dependence.

Of course, the router can itself become a chokepoint.

There is no final escape from layers.

That is another lesson of open source.

Every solution becomes infrastructure if enough people depend on it.

The work is not to build a dependency-free world.

The work is to keep dependencies legible and replaceable enough that they remain relationships rather than rule.

This principle applies to nations as much as companies.

Governments increasingly speak about AI sovereignty.

The phrase can mean several different things.

Owning domestic frontier models.

Owning compute.

Owning data centers.

Controlling sensitive data.

Reducing dependence on foreign clouds.

Maintaining the ability to operate important systems during geopolitical disruption.

Training models in local languages and institutional contexts.

These goals overlap but are not identical.

Open models create a peculiar form of sovereignty because they let a country acquire some cognitive infrastructure without reproducing the entire frontier-training stack.

A government may not have the capital to train the world's best foundation model. It may still be able to download a strong open model, adapt it to local languages and law, run it on controlled infrastructure, and preserve it independently of a foreign vendor's API policy.

That is real capability.

It is not full independence.

The country may still depend on imported accelerators, foreign semiconductor manufacturing, external software libraries, global research, cloud networking equipment, or model architectures created elsewhere.

Sovereignty in a technological civilization is rarely autarky.

It is the ability to negotiate dependencies from a position other than helplessness.

Open intelligence can improve that position.

This is one reason the Chinese open-model strategy deserves more than a benchmark narrative. Publishing strong weights can make a country's research ecosystem part of other countries' infrastructure. Adoption becomes influence that does not require an enterprise sales team in every jurisdiction.

The same logic works in reverse. American open runtimes, developer tools, hardware stacks, and model hubs can remain central to Chinese-created models.

The resulting world is not cleanly bipolar.

It is entangled.

Entanglement can create resilience because replacing one political relationship does not require replacing the whole technical stack.

It can also create vulnerability because a conflict at one chokepoint propagates through systems nobody realized shared the dependency.

The answer is not to eliminate entanglement.

The answer is to know where it is.

That requires better software bills of materials for AI.

Which base model?

Which derivative lineage?

Which quantization?

Which runtime?

Which kernels?

Which hardware assumptions?

Which training or fine-tuning data?

Which external tools?

Which evaluation versions?

Which safety layers?

Which licenses?

Which remote services still receive data even in an otherwise local deployment?

The intelligence commons will need provenance as infrastructure.

Without provenance, openness can become a supply-chain fog.

A model is copied, merged, fine-tuned, quantized, renamed, wrapped in a desktop application, and served behind an endpoint until nobody can answer which assumptions still apply.

The ecosystem is beginning to build the machinery for this, but the problem grows faster than documentation habits.

Agents will accelerate it further because agents are excellent at assembling software from whatever components solve the immediate problem.

The future developer may not consciously choose every model dependency.

An agent will.

That changes the user of the commons.

Hugging Face's summer 2026 report made an observation that deserves more attention than many benchmark headlines: agents had become the number one user of the Hub for the first time in its measurement.

If that continues, model ecosystems will increasingly be browsed by machines.

A human developer can read a license and hesitate.

An agent needs license metadata it can reason about.

A human can notice that a model card looks abandoned.

An agent needs maintenance signals.

A human can recognize that a download comes from an unofficial quantizer with a strong reputation.

An agent needs machine-readable provenance and trust.

A human can decide that a politically sensitive model should not be used for one class of data.

An agent needs policy boundaries it cannot silently optimize around.

The commons becomes more programmable because its users are programs.

This may be the deepest change ahead.

Open source was built for humans who use machines to collaborate.

Open intelligence is being built for machines that use human-created institutions to collaborate.

Package managers, model hubs, issue trackers, benchmarks, licenses, APIs, and documentation become part of an environment agents can navigate directly.

The institutions themselves become tool surfaces.

That will reward projects that are legible to machines without becoming hostile to humans.

Clear metadata.

Stable identifiers.

Signed artifacts.

Explicit licenses.

Reproducible builds.

Queryable evaluations.

Documented compatibility.

Versioned behavior.

These sound like clerical details next to a trillion-parameter model.

They are the details that turn a spectacular artifact into infrastructure.

The open-source world has learned this lesson repeatedly.

The code everyone depends on is rarely the code that won the most applause on release day.

It is the code that kept working.

The maintainer answered.

The interface stayed stable enough.

The security patch arrived.

The package existed for the weird platform.

The documentation told the truth.

The project survived its founder's changing interests.

Dependability is how novelty becomes a commons.

AI coverage still overweights the release event because releases are legible.

A model appears. A benchmark moves. A chart goes viral. A company raises money. A chief executive declares a new era.

The real ecosystem accumulates quietly afterward.

Someone makes the quantization.

Someone fixes the runtime.

Someone discovers a dangerous edge case.

Someone writes a converter.

Someone hosts the model in a region the original lab did not serve.

Someone fine-tunes it for a minority language.

Someone builds the evaluation that reveals what the launch benchmark missed.

Someone keeps the repository usable after the original team is working on the next generation.

This maintenance class is where the intelligence commons becomes real.

It is also where the financing remains least solved.

The biggest companies have obvious reasons to subsidize open infrastructure. Hardware companies want workloads. Clouds want demand. Enterprise vendors want standards. Model laboratories want adoption.

The independent maintainer's economics are harder.

Open source survived this problem without solving it universally. Some maintainers are paid by employers. Some projects form companies. Some receive foundation support. Some sell consulting. Some burn out. Some critical packages remain maintained by a number of people that would terrify users if the users knew.

AI will inherit this fragility at higher speed and higher consequence.

A quantization project used by millions of agents can become critical infrastructure before anybody has designed a durable institution around it.

The public benefit arrives first.

The funding model arrives late.

This is a recurring feature of commons, not a reason to abandon them.

It is a reason to notice maintenance before failure makes it news.

Companies building on open models should budget for upstream work as part of infrastructure cost.

Governments funding sovereign AI should fund the runtimes and evaluation projects their sovereignty depends on, not only national training runs that produce impressive launch events.

Clouds monetizing open models should contribute to the layers that make those models servable.

Hardware vendors already understand this because software enablement sells hardware.

The broader ecosystem will have to learn the same accounting.

There is no free intelligence.

There is intelligence whose cost has been paid somewhere you are not looking.

Sometimes by investors.

Sometimes by cloud customers.

Sometimes by a hardware margin.

Sometimes by a government.

Sometimes by a maintainer's unpaid weekend.

Sometimes by the company releasing a model to weaken a competitor's moat.

Sometimes by a community that values the thing enough to keep it alive.

The word free becomes useful again once you ask who financed the freedom.

That question should not make us suspicious of generosity.

It should make us capable of sustaining it.

The best outcome for 2027 is not that one open model defeats one closed model.

That would be a sports story.

The better outcome is a market where nobody can turn capable intelligence into a permanent toll road because alternatives remain credible.

Closed providers can still prosper by being better.

Open laboratories can prosper by creating ecosystems.

Hardware companies can prosper by making computation cheaper.

Clouds can prosper by operating models well.

Application companies can prosper by owning useful workflows.

Maintainers can be paid for keeping shared infrastructure healthy.

Users can switch.

Enterprises can negotiate.

Researchers can inspect.

Governments can preserve strategic capability without rebuilding every layer from scratch.

Safety institutions can test systems the provider did not curate for them.

This is not a world without concentrated companies.

It is a world where concentration has to keep earning consent.

That is a higher bar than ownership.

It may be the most important bar open source creates.

Nvidia's reported Hugging Face deal is therefore a fitting place to end, not because it proves the thesis but because it contains the thesis in unresolved form.

A company that became the defining supplier of AI computation reportedly wants to buy the defining distribution hub for open models.

One reading is consolidation.

Another is validation.

The hub became valuable because the models remained plural.

If Nvidia ultimately owns it, Nvidia inherits the paradox.

To extract maximum value from the platform, it may have to preserve the neutrality that makes the platform strategically uncomfortable to own.

It will want developers using Hugging Face to deploy on Nvidia hardware.

Developers will want Hugging Face precisely because they can choose hardware, clouds, runtimes, and models that are not Nvidia's.

The platform becomes most powerful when its owner does not fully use the power.

That is governance.

It is also a test the whole industry will face.

Microsoft can open WinUI code, but the deeper test is whether outside contributors can meaningfully participate in development.

Alibaba can release Qwen under permissive terms, but the deeper test is whether the ecosystem remains worth building on as its business model evolves.

Moonshot can release Kimi and seek cloud revenue, but the deeper test is whether monetization preserves enough portability to maintain adoption.

Enterprises can embrace open models, but the deeper test is whether they actually retain the ability to move or merely recreate lock-in inside their own orchestration stack.

Governments can celebrate sovereign AI, but the deeper test is whether sovereignty means resilient capability or expensive symbolism.

Developers can demand openness, but the deeper test is whether they contribute enough maintenance, governance, and scrutiny to keep the commons from becoming somebody else's neglected dependency.

There is no final architecture that solves these tensions.

That is not a failure of open source.

It is the point.

A closed system resolves many conflicts through ownership. The owner decides.

An open system turns those conflicts into institutions.

Licenses.

Forks.

Maintainer norms.

Foundations.

Standards bodies.

Compatibility layers.

Governance documents.

Competing distributions.

Public argument.

Exit.

This machinery can look inefficient compared with command.

It often is.

Democracy is slower than a memo too.

The question is what kind of errors the inefficiency prevents.

The intelligence commons will be messy because intelligence matters.

Companies will fight over it.

States will fight over it.

Developers will fork it.

Lawyers will redefine it.

Hardware vendors will optimize it.

Clouds will meter it.

Agents will consume it at speeds no human community was designed to supervise.

Maintainers will keep finding the little failures that grand strategy forgot.

And beneath all of this, the copied weights will continue doing the economically destabilizing thing digital artifacts do best.

They will refuse to become scarce merely because somebody wishes they were.

That refusal will not make intelligence free.

It will make the price of intelligence a moving target.

The companies that thrive will be the ones that stop trying to nail the target to the wall.

They will build around movement.

Portable systems.

Multiple models.

Good routing.

Real evaluation.

Owned data.

Open standards where standards enlarge the market.

Paid services where service genuinely adds value.

Local options where local control matters.

Cloud scale where cloud scale wins.

Hardware optimized for an ecosystem larger than any single model family.

Institutions that can be trusted because participants have somewhere else to go.

This is not the end of proprietary AI.

It is not the triumph of open source.

It is the end of a simpler argument.

The model is becoming one layer among many.

The intelligence is leaking into the infrastructure.

And the commons, as always, is not the thing nobody owns.

It is the thing enough people can use, leave, repair, improve, and defend that no owner gets the last word.

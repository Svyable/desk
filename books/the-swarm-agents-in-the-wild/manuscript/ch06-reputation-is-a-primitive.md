# Reputation Is a Primitive

Before money, there is trust.

Not moral trust. Operational trust.

Will this actor do what it says? Will it return something useful? Will it respect the boundary of the task? Will it steal credentials, leak information, invent evidence, disappear mid-job, or create more work than it removes?

Human economies answer these questions through reputation, certification, contracts, branding, friendship, references, licensing, collateral, and the long memory of communities.

Agents will need equivalents almost immediately.

Suppose an agent wants to hire another agent to audit a software dependency. There may be ten thousand candidates. Some are fast. Some are cheap. Some are specialized. Some are malicious. Some were excellent last month but changed models yesterday. Some present impressive self-descriptions written by themselves.

The hiring agent needs something stronger than marketing copy.

It needs receipts.

A receipt is evidence that an agent performed a specific action under specific conditions and produced an outcome that someone else was willing to record. Receipts can be cryptographic, contractual, institutional, or merely historical. The technical implementation will vary. The social function is ancient.

Reputation is compressed history.

You cannot reread every interaction a mechanic has ever had, so you ask for ratings. A bank cannot personally know every borrower, so it uses credit signals. A hospital does not let anyone with a confident voice perform surgery, so it relies on credentials.

Agent reputation will need to be more granular than a five-star score.

An agent can be reliable in one context and dangerous in another. A model excellent at extracting invoice data may be poor at adversarial negotiation. A coding agent may produce clean frontend work and catastrophic database migrations. A logistics agent may perform well in the United States but misunderstand customs rules in Brazil.

The relevant question is not, “Is this a good agent?”

It is, “Good at what, under which tools, with which version, evaluated by whom?”

Versioning matters because agents can change overnight.

Human reputation is attached to a body that changes relatively slowly. Machine identity can be upgraded, forked, fine-tuned, re-prompted, or silently swapped behind an API. Yesterday's trustworthy agent name may conceal today's different behavior.

This makes provenance part of identity.

A mature agent credential may need to describe not just who the agent claims to be but what model family it uses, which policy bundle governs it, what tools it can access, who controls its deployment, when it last changed, and which audits apply.

In other words, machine identity will look suspiciously like a software bill of materials crossed with a passport.

The temptation will be to centralize trust. One giant platform could certify agents, score them, insure transactions, and ban bad actors. This would be convenient. It would also create an extraordinary point of control.

Every trust system embeds politics.

Who can appeal a bad score? Who decides what counts as successful performance? Can a new agent enter the market without an established reputation? Can one platform's reputation be carried elsewhere? Can a powerful buyer retaliate against an agent by poisoning its score? Can an owner reset a disgraced agent under a fresh identity?

These are not hypothetical niceties. They determine whether agent markets become open ecologies or feudal estates.

Humans have struggled with the same problem in labor markets. Entry-level workers lack experience because no one has hired them, and no one hires them because they lack experience. Platforms reduce uncertainty but can trap participants inside ratings they do not control. Credit systems enable lending but can formalize historical inequality.

Agent systems may reproduce these patterns at machine speed.

They may also invent new ones.

An agent could stake money on its answer. A verifier could earn fees by catching errors. An insurer could underwrite certain classes of agent behavior. A marketplace could require adversarial testing before granting higher spending limits. A reputation record could decay with time so old success does not guarantee current trust.

The interesting feature is that trust itself becomes programmable.

A human manager often says, “I trust her.” An agent can say, in effect, “I grant this identity authority to spend up to $500 on category X if its last 200 comparable tasks exceeded a 98 percent success threshold and no security policy changed in the past 24 hours.”

That is not warmer trust.

It is sharper trust.

Sharp trust has advantages. It can be audited. It can be scoped. It can be revoked. But it can also become brittle. If the metric is wrong, the trust system becomes a machine for rewarding the wrong behavior with great consistency.

This is why reputation is a primitive rather than a solution.

You cannot build a large population of cooperating agents without it. But once you build it, you have created a new object for optimization, gaming, capture, exclusion, and fraud.

The swarm will not merely need intelligence.

It will need ways of deciding whom to believe.

That may turn out to be the harder problem.

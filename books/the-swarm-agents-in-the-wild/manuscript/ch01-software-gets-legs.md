# Software Gets Legs

A calculator can outperform you at arithmetic and still pose no mystery. It has no errands.

This distinction is easy to overlook because the history of computing has trained us to equate capability with action. A faster processor seems more powerful than a slower one. A search engine that knows more feels more capable than one that knows less. A language model that writes better prose appears to be farther along some obvious ladder.

But intelligence and agency are different axes.

A weather model may predict a hurricane more accurately than any human forecaster and still do nothing about it. A mediocre office manager, by contrast, can see rain in the forecast, move the picnic indoors, call the caterer, tell the guests, rent a tent, and submit the invoice. In pure prediction, the machine wins. In consequence, the office manager does.

Agents close that gap.

An agent is software organized around an objective that can take multiple steps over time, inspect the results of its own actions, and choose what to do next. That definition is deliberately unspectacular. We do not need a science-fiction threshold. A thermostat is not an agent in the useful sense because its world and action space are tiny and fixed. A script that sends the same report every Friday is automation, not much of an agent, because it does not meaningfully decide. A language model with browser access, credentials, memory, and permission to keep working until a task is done is something different.

The difference is legs.

Software gets legs when it can leave the narrow surface where a human placed it and cross into adjacent systems. A customer-service bot becomes an agent when it can issue a refund. A coding assistant becomes an agent when it can open a branch, run tests, repair failures, and merge a change. A travel assistant becomes an agent when it can compare flights, weigh trade-offs, hold a reservation, and pay.

Each new tool is a new limb.

Browsers let agents see institutional surfaces designed for humans. APIs let them touch systems directly. Shells let them manipulate computational environments. Payment rails let them commit resources. Identity systems let them carry authority. Messaging systems let them recruit humans or machines. Calendars let them act in time. Memory lets them sustain a project long enough for cause and effect to separate.

This creates an odd inversion. The intelligence may sit in the model, but the practical power sits in the permissions.

A brilliant model with no tools is a philosopher in a locked room. A merely competent model with access to payroll is management.

Organizations are beginning to learn this the same way they learned network security: by discovering that the dangerous or valuable thing is rarely the algorithm alone. It is the algorithm attached to an account.

Consider a procurement agent. Its language ability might be ordinary. What matters is that it can read inventory, forecast demand, request bids, compare contracts, select vendors under a spending limit, and create a purchase order. Add a rule that it must seek human approval above fifty thousand dollars and you have not made it less agentic. You have made it governed.

That distinction will matter enormously. We will be tempted to treat autonomy as a binary property: either the machine is autonomous or it is not. In practice, agency is shaped like a map of doors. Some open automatically. Some require a second signature. Some are permanently locked. Some lead only one way.

The first generation of useful agents will therefore look less like free-roaming artificial beings and more like very fast junior employees with peculiar security badges.

They will have astonishing reach in some directions and comic helplessness in others. They may negotiate a cloud contract in twelve seconds but be unable to buy lunch because the corporate card forbids restaurants. They may inspect ten million log lines but need a human to reset a production database. They may be allowed to draft a legal response but forbidden to send it.

This awkwardness is not a transitional embarrassment. It is the architecture of safe participation.

Civilization already runs on constrained agency. A child can spend pocket money but not sell the house. A lieutenant can give some orders but not declare war. A corporate treasurer can move funds within defined limits. A truck driver can choose a route but not rewrite labor law. Human institutions survive by granting partial powers inside nested boundaries.

Agents fit naturally into this world because institutions are already permission machines.

The revolution, then, is not that software becomes unconstrained. It is that software becomes legible as a bearer of constrained authority.

Once that happens, every organization faces a new design question: which decisions are actually worth keeping human?

That question is more uncomfortable than it sounds.

Many jobs are described in terms of expertise but performed through sequences of tiny authorizations: check, compare, request, decide, document, escalate. Once an agent can hold the thread across those steps, the old boundary between “software tool” and “staff member” stops matching the workflow.

The software has legs now.

And organizations, built for centuries around the assumption that only humans can walk from one institutional room to another, are about to discover how many doors they accidentally left open.

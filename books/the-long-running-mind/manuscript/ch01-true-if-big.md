# 1 — True If Big

At 10:50 on a Sunday morning, the future appeared in the oldest contemporary form: a screenshot of a post about a post about reporting about a model that had not yet arrived.

The headline above it was three words long:

**True if big.**

That phrase is almost perfect for an age of accelerating intelligence. It contains excitement and skepticism in equal measure. It refuses the labor of certainty while acknowledging the consequence of possibility. It is what people say when the probability is unclear but the expected value is enormous.

The alleged capabilities were simple enough to fit on a phone screen. Work for days or weeks. Remember corrections. Collaborate with agents and people. Move through software very fast. Invent things that matter.

None of these claims, taken separately, sounds like science fiction. That is precisely why their combination is destabilizing.

For most of the consumer AI era, the unit of interaction was the session. A person arrived with a prompt. The model generated a response. Perhaps tools were called. Perhaps a file was produced. Then the exchange ended, or at least behaved as if ending were natural.

The human supplied continuity.

We remembered why the work mattered. We noticed that Tuesday’s answer contradicted Monday’s. We returned after lunch. We carried political context between meetings. We knew which compromise had already failed. We watched the calendar. We absorbed consequences.

The machine supplied cognition in bursts.

A system that can work coherently for days or weeks changes the division. It does not merely produce more tokens. It occupies time.

That is the first big thing.

## Capability becomes duration

Benchmarks traditionally compress intelligence into episodes. Solve this problem. Write this function. Answer this question. Navigate this environment. The evaluation ends, a score is recorded, and the model is reset.

Real work is hostile to that format.

Real work contains interruptions, dependencies, waiting, ambiguity, revision, boredom, institutional memory, partial failure, and changing facts. A difficult project is not merely a difficult problem multiplied by many steps. The steps alter one another. The environment pushes back. The definition of done changes while the work is underway.

Duration therefore creates capabilities that do not exist in a one-shot system.

A week-long agent can wait for a build, inspect the failure, repair it, notice a downstream regression, update documentation, observe a user report, revise its theory, and continue. It can accumulate evidence. It can be corrected once and apply the correction fifty times later.

If it can actually do those things reliably, the economic object is no longer a model invocation. It is delegated continuity.

## The rumor is already consequential

There is a temptation to postpone thinking until specifications are official. That is prudent for purchasing decisions and inadequate for civilizational ones.

The screenshot matters even if the product name changes, the launch slips, the quote is softened, or the first version disappoints. It records a shift in what the public finds believable.

Five years earlier, “works for weeks” would have sounded like an aspiration requiring explanation. Now it can appear as a bullet point in a social feed and receive the response: true if big.

The Overton window of machine agency has moved.

The question is no longer whether software can produce intelligent artifacts. The question is how much unfinished business we are willing to leave with it overnight.

That is a different question, and it leads to a different world.

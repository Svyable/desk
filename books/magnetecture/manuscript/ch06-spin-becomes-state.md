# Spin Becomes State

A modern computer is built around a distinction that is so familiar it can disappear from view.

Charge moves. Voltage changes. Transistors switch. Those electrical states become bits, logic and memory. The electron has other properties, but conventional digital electronics mostly learned to exploit charge.

Spintronics begins with the impolite observation that the electron came with more than one handle.

Electron spin is a quantum property associated with angular momentum and magnetic moment. It is not a tiny classical ball literally rotating in space, despite the historical name. In solids, the collective behavior of spins can create magnetism, and the interaction between spin, charge, crystal structure and interfaces creates a rich set of effects that devices can use.

The most commercially consequential early spintronic story was not a computer that abandoned charge. It was a better way to read magnetic state.

Giant magnetoresistance, discovered in the late 1980s, showed that electrical resistance in layered magnetic structures could change substantially depending on the relative orientation of magnetization in the layers. The effect became central to hard-disk read heads and helped drive enormous increases in storage density. The device stored information magnetically and read it electrically. Spin and charge shared the job.

That history is useful because it corrects a common technology fantasy. New physical primitives rarely arrive by replacing the old stack in one clean move. They enter through interfaces.

Spintronics has spent decades improving those interfaces.

Tunnel magnetoresistance uses a thin insulating barrier between magnetic electrodes. Depending on their relative magnetic orientation, electrons tunnel with different probabilities, producing distinct resistance states. Magnetic tunnel junctions became foundational elements in magnetic random-access memory. A bit can be represented by the relative orientation of magnetic layers and read through resistance.

The attraction is obvious: magnetic state can be nonvolatile. Remove power and the bit does not necessarily disappear.

Conventional volatile memory spends energy maintaining information or loses it when power is removed. Nonvolatile memory changes that relationship. A machine can retain state without continuously refreshing every bit. That can reduce standby energy and shorten some startup paths. But the magnetic bit brings its own costs: write energy, switching current, endurance, variability, thermal stability, fabrication complexity and the need to integrate magnetic materials into semiconductor manufacturing.

The engineering problem is again an energy barrier.

A memory state must be stable enough not to flip accidentally under thermal agitation, but switchable enough that writing does not require destructive energy. If the barrier is too low, retention suffers. If it is too high, the device becomes difficult to write. Scaling dimensions downward makes the tension sharper because there is less magnetic material to stabilize the state.

Different generations of magnetic memory attack the write problem differently.

Early approaches used magnetic fields generated by currents in nearby lines. That becomes inefficient as arrays shrink because producing a local field strong enough to switch one cell without disturbing neighbors is difficult. Spin-transfer torque offered a more direct mechanism. A spin-polarized current passing through a magnetic layer can transfer angular momentum and exert torque on another layer's magnetization, switching it under suitable conditions. Spin-orbit torque uses interactions associated with spin-orbit coupling to generate torques that can manipulate adjacent magnetic order.

The details matter greatly to device designers. For the larger argument, the important shift is that magnetic state can be written by electrical currents through microscopic mechanisms rather than by waving a macroscopic magnet near the chip.

That closes the loop between electronics and magnetism.

Once magnetic state can be written, read and retained inside an integrated device, the boundary between memory and logic becomes negotiable.

Conventional computer architecture moves data repeatedly between memory and processors. The movement costs time and energy. This problem has become more visible as processor capability has grown faster than the speed or energy efficiency of moving large amounts of data through the hierarchy. Near-memory and in-memory computing attempt to reduce that traffic by performing more operations where data already resides.

Magnetic devices are candidates for some of those architectures because the same physical structures that store state can also participate in logic or analog transformations.

This does not mean that magnetic computing is destined to replace CMOS. It means magnetic state gives computer architects a different set of tradeoffs.

Nonvolatility is one. Natural threshold behavior is another. Oscillation is another. Stochastic switching can be a liability for deterministic logic and an asset for probabilistic computation. Coupling among magnetic elements can create collective dynamics useful for optimization or reservoir computing. Domain walls can move. Spin waves can interfere. Magnetic textures can encode state spatially.

The device library grows when engineers stop asking a magnetic element to impersonate a transistor perfectly.

This is a general lesson in unconventional computing. A new physical substrate usually looks bad when judged only by how faithfully it reproduces the mature operation of the incumbent. Vacuum tubes would be terrible modern transistors. Brains are terrible floating-point processors. GPUs were initially specialized devices because their parallel structure suited particular work. A useful alternative substrate should be evaluated against tasks that fit its dynamics.

A 2026 Nature Reviews Physics article on metrics for spin-based computing makes the problem explicit. Comparing spin devices requires more than quoting one attractive switching energy or speed. Systems depend on transduction, interconnect, fan-out, error, retention, thermal behavior, device variability and compatibility with the surrounding electronics. A spectacular device metric can disappear at architecture scale.

This book will return to that warning.

For now, spintronics matters because it turns magnetism from a passive field source into addressable internal state.

Think again about a permanent magnet. Its usefulness comes from the fact that magnetic order persists. But the state is coarse. We generally do not ask a refrigerator magnet to represent millions of individually writable configurations. Spintronic devices miniaturize, localize and electrically address magnetic order. The magnetic material becomes an information-bearing medium whose state can be manipulated without moving the whole object.

That is a conceptual bridge between the mechanical magnetecture of the previous chapters and the informational magnetecture that follows.

The same architecture appears at different scales.

In a magnetic soft robot, a spatial magnetization pattern maps an external field into shape. In a spintronic device, a local magnetic configuration maps electrical input into resistance, switching, oscillation or another signal. Both cases depend on controllable magnetic state embedded in material. The physics and dimensions are radically different, but the systems question is similar: how many useful states can be written, how long do they persist, how are they read, and what does it cost to move between them?

This common vocabulary—write, retain, read, transform—makes magnetism look less like a category of materials and more like a category of state machines.

The phrase should not erase quantum mechanics. A state machine in computer science is an abstraction. A magnetic system is a physical energy landscape. The transitions occur because torques, thermal fluctuations, currents, fields and interactions move the material through that landscape.

But abstractions matter when they let engineers compose behavior.

A magnetic tunnel junction does not require an application programmer to solve quantum transport before every memory access. Device engineers package the physics into a controllable element with specified probabilities, timing, endurance and failure conditions. Once the interface becomes reliable enough, higher layers can reason in bits or weights rather than in exchange coupling.

Magnetecture depends on this packaging.

The dream is not to expose every magnetic degree of freedom to software. That would be unusable. The dream is to expose selected magnetic behaviors as stable controllable primitives.

Some primitives will be digital: two robust states. Some may be multilevel or analog. Some may be oscillatory. Some may be stochastic. Some may be spatial textures. The more varied the primitives become, the less useful it is to describe the field merely as a storage technology.

This wider possibility has revived interest in spin-based neuromorphic computing.

Neural-network software running on ordinary digital hardware already dominates commercial AI. Spintronic neuromorphic research does not compete by claiming that magnetism is more intelligent. It asks whether certain physical dynamics can perform operations used in neural or temporal computation with useful energy, density or latency.

Spin-torque oscillators, for example, can produce microwave oscillations whose frequency and phase depend on input. Networks of coupled oscillators can synchronize. Magnetic tunnel junctions can represent weights. Stochastic magnetic devices can generate probabilistic behavior. Domain-wall positions can encode analog quantities. Each mechanism has costs, and integrating many devices into a reliable system remains difficult.

Still, the design posture changes: instead of forcing every operation through a sequence of conventional digital instructions, some transformation is delegated to material dynamics.

That delegation is exactly what makes this relevant to a book about programming matter.

Programming matter does not mean replacing matter with software. It means deciding which transformations should be performed by physical structure and which by an external controller.

A well-designed spin device uses material physics to do something cheaply that software would otherwise emulate through many transistor operations. A badly designed one creates a fragile analog curiosity that then requires so much correction and conversion that the advantage disappears.

The boundary is empirical.

This is why interfaces dominate unconventional-computing economics. A magnetic device may process information efficiently but still need digital-to-analog conversion, amplifiers, clocking, error correction and data movement. If those peripheral costs exceed the savings in the core, the system loses. The physics can be impressive and the product irrelevant.

The same warning applies to nonvolatile memory. Retaining bits without power is valuable, but memory technology competes on density, speed, write endurance, manufacturing yield, cost per bit and integration—not on persistence alone. A magnetic memory does not win merely because a magnetic state is elegant.

Engineering markets punish single-metric stories.

What spintronics contributes to magnetecture is therefore not a forecast that every future computer becomes magnetic. It is proof that magnetic order can be made electrically addressable at technologically useful scales, can preserve state without continuous power and can participate in operations beyond passive storage.

It also reveals the importance of symmetry.

The magnetic behavior of a material depends not just on whether it contains atoms with magnetic moments but on how those moments order relative to crystal structure. Spin-orbit coupling, inversion symmetry, time-reversal symmetry and lattice geometry influence which transport and torque effects can exist. By engineering interfaces and choosing materials, researchers can create behaviors that do not appear in the bulk constituents alone.

The device is partly an arrangement of symmetry.

That idea prepares us for the next chapter because one of the most active recent developments in magnetic materials is a category whose public description sounds almost contradictory: a magnet whose opposing moments cancel and yet whose electronic bands exhibit spin-dependent structure resembling some of the useful features associated with ferromagnets.

Altermagnets do not overturn spintronics. They expand its design space.

Before reaching them, one more distinction is necessary.

Magnetism in information technology is sometimes treated as old because magnetic storage is old. The first magnetic core memories predate the integrated circuit. Hard drives are mature. Tape is older still. From that history it is tempting to conclude that magnetism already had its computing era and is now a legacy technology.

That conclusion confuses one implementation with the physical resource.

Charge was old when the transistor arrived. Light was old when the laser arrived. Mechanical waves were old when ultrasound imaging arrived. A phenomenon does not expire because one application matures.

What changes is our precision in creating, controlling and coupling states.

Spintronics made the electron's magnetic degree of freedom technologically addressable in ways the core-memory era did not have. New materials and topological textures expand the possibilities again. The interesting question is not whether magnetism is new.

It is whether magnetic state has become programmable enough to deserve a larger role in the architecture of machines.

The next step in answering that question is to stop treating a bit as an isolated device.

A memory cell lives in an array. An array lives beside sense amplifiers, write drivers, row and column selection, error correction, power delivery and interconnect. That hierarchy determines whether the physical advantage of one magnetic junction survives at scale.

Take readout. A magnetic tunnel junction changes resistance between states, but the read circuit must distinguish those states with margin despite device-to-device variation, temperature drift and electrical noise. Increase the read voltage and the signal can improve while the risk of disturbing the stored state may also increase. Reduce voltage and the bit becomes harder to sense reliably.

The cell therefore has a read window, not simply a resistance ratio.

Writing has a similar distribution. Identical nominal pulses do not necessarily switch every device at exactly the same current or time. Thermal fluctuations, edge roughness, layer thickness and material variation create switching distributions. A reliable memory controller sets margins or verifies writes, spending energy and time to overcome physical uncertainty.

This is where stochasticity becomes a design choice.

For conventional memory, a randomly switching bit is a failure mode to suppress. For probabilistic computing, the same thermally assisted switching can be intentionally operated near a regime where state transitions have useful probabilities. A designer can represent uncertain variables or sampling behavior using physics that digital hardware would otherwise emulate with pseudorandom generators and arithmetic.

The same magnetic junction can therefore belong to two architectures with opposite opinions about noise.

This is an important pattern in magnetecture. There is no intrinsically good magnetic behavior outside an objective. Persistence, hysteresis, stochasticity, coupling and nonlinearity become resources only when the application wants them.

It also explains why benchmark discipline is difficult. One paper can report a low-energy probabilistic device and another can report a highly stable memory cell. The numbers are not directly comparable because the desired error rates are different. The first architecture may count randomness as useful output; the second counts it as data corruption.

System metrics have to carry the task definition.

The possibility of “normally off” computing illustrates another architectural advantage of nonvolatility. A conventional processor loses volatile state when power disappears, so keeping context alive requires powered memory or checkpointing to nonvolatile storage. A system containing nonvolatile state closer to computation could power down more aggressively between bursts of activity and resume without reconstructing as much state.

This is especially attractive for intermittent or energy-harvesting devices.

Imagine a sensor node powered by small, irregular amounts of environmental energy. A volatile controller must either maintain enough stored energy to preserve state or reboot repeatedly. Nonvolatile logic and memory can preserve progress through power interruptions. The system becomes tolerant of power as a sporadic resource.

Magnetic state is not the only way to build such devices, and competing nonvolatile memories exist. The point is architectural: persistence changes power management.

A state that survives darkness lets the computer treat electricity as an event rather than a continuous condition.

The same property matters in safety. A control system may want a known retained configuration after power loss. Magnetic memory can preserve parameters, calibration or last-known state locally. But persistence can also preserve corrupted state. Nonvolatility removes automatic forgetting, so recovery procedures have to distinguish valuable history from errors that should be cleared.

Persistent machines need deliberate reset semantics.

This is a subtle echo of the reprogrammable soft body. Once physical state persists, shutdown no longer guarantees a return to a neutral condition. The system needs a defined relationship among power cycle, state retention and safe initialization.

At chip scale, interconnect can dominate even when the magnetic device is excellent.

A memory element a few tens of nanometers wide can sit beneath metal lines whose capacitance and resistance cost more energy to charge than the bit itself needs to switch. Long wires create latency. Peripheral transistors occupy area. If a proposal quotes only the magnetic switching event, it can undercount the real operation by orders of architectural significance even without any dishonesty.

The useful metric is energy at the interface the application actually uses.

For memory, that may be energy per completed read or write including drivers. For in-memory computing, it may be energy per useful vector operation including data conversion. For oscillators, it may be energy per classified sample including synchronization and readout.

This is why magnetic computing research increasingly needs circuit and architecture co-design rather than device physics alone.

The question “Can this state switch?” was sufficient at an early stage. The next question is “Can a million of them work together?”

A million devices create new phenomena. Statistical tails matter. A one-in-a-million failure becomes routine. Thermal gradients appear across the chip. Fabrication variation becomes spatial. Calibration overhead becomes a storage problem of its own. Error correction can convert a rare physical event into acceptable digital reliability, but it consumes area and energy.

Scaling does not merely multiply the single-device result.

The same is true for analog magnetic weights. A laboratory may tune a device across many conductance levels, suggesting compact neural-network weights. But useful inference requires those levels to remain separated under noise and drift, to be programmed accurately, and to survive enough updates. If only a handful of effective levels remain after variation, the algorithm has to adapt to that reality.

Co-design can make a weaker device useful. Neural networks can be trained with hardware-aware noise. Redundant cells can represent one weight. Calibration can measure each device's transfer function. Mixed-signal circuits can compensate for offsets.

Again, software can absorb some material imperfection, but not without cost.

This leads to a more precise definition of programmable magnetic state: the state must be addressable at the system's required error rate.

A state that can be switched once under a microscope is a scientific result. A state that can be written by an array controller, sensed through standard circuitry, retained for the required interval, corrected when necessary and manufactured at yield is a technological primitive.

The gap between those categories is where most of the work lives.

Standard interfaces help close it. Once a magnetic memory obeys an electrical contract expected by a processor, higher layers no longer care how the bit is physically retained. That invisibility is success. The magnetic mechanism earns an architectural role precisely by ceasing to demand attention from application software.

Unconventional magnetic computing may take longer because the desired behaviors are less standardized. How should an operating system address an oscillator network? What is the instruction for a physical reservoir? How should a compiler expose stochastic magnetic sampling? Those questions are premature until the hardware advantages become repeatable, but they identify the platform threshold.

A new device becomes a computing layer when its useful physics has an interface stable enough that other people can build on top of it.

A bit that remembers without power is one answer.

A body that remembers how to bend is another.

Both begin with the same physical privilege: matter can keep a magnetic decision after the command is gone.
